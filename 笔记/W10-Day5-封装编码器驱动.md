# W10 Day5 —— 封装编码器驱动

> 目标：把"正交解码 + 测速"封装成可复用驱动，接口参数化（线数 / 倍频 / 减速比 / 采样周期）。
> 交付：`Hardware/ENCODER/encoder.c|h`，实测验证节拍精度 99.8%、转速量级正确。

---

## 一、接口设计

```c
/* 采样周期（ms）—— 也是 PID 的 dt */
#define ENCODER_SAMPLE_MS   10

int     ENCODER_Init(TIM_TypeDef *tim, uint16_t lines, uint16_t gear_x10);
void    ENCODER_Update(void);              /* 由节拍中断每 SAMPLE_MS 调用一次 */
int32_t ENCODER_GetPosition(void);         /* 累计位置（计数，正 + 反 −）*/
void    ENCODER_ResetPosition(void);
int32_t ENCODER_GetRpm10(void);            /* 转速：0.1 rpm（750 = 75.0 rpm）*/
int32_t ENCODER_GetCountsPerSec(void);     /* 转速：计数/秒（调试用）*/
```

---

## 二、三个关键设计决策

### ① 驱动**不占用节拍定时器** —— 由应用层调用 `ENCODER_Update()`

| 方案 | 问题 |
|---|---|
| 驱动内部配 TIM4 做节拍 | **驱动绑死"必须用 TIM4"** → 应用层想用 TIM4 就冲突 |
| **应用层每 10ms 调用 `ENCODER_Update()`** | **驱动只关心"被调用了"，不关心谁调的** ✅ |

**⭐ 这叫"依赖倒置"** —— **驱动不依赖具体的节拍源。**

**⚠️ 隐含契约：`ENCODER_Update()` 必须严格按固定周期调用。** 这个契约要写进注释，否则调用方用错就全错。

### ② 节拍中断里**直接调用**，不放主循环

```c
void TIM4_IRQHandler(void)
{
    if (TIM4->SR & (1UL << 0))
    {
        TIM4->SR = (uint16_t)~(1UL << 0);
        ENCODER_Update();          /* ★ 在 ISR 里，保证严格 10ms */
    }
}
```

**为什么**：**`ENCODER_Update()` 只有约 10 条指令**，放 ISR 里能保证严格周期；放主循环会被 `KEY_Scan()` 之类的阻塞拖偏 → **`dt` 不准 → rpm 算错 → PID 也错**。

### ③ **`ENCODER_Init` 里做参数检查**（驱动的"合同"）

```c
if (tim == 0)                return -1;
if (lines == 0)              return -1;
if (gear_x10 == 0)           return -1;      /* 防除零 */
if (lines > 10000)           return -1;      /* 防溢出 */
if (1500000UL % ENCODER_SAMPLE_MS != 0) return -1;   /* k 必须整除 */
```

**⭐ 和 `TIMER_Setup` 一样 —— 参数检查是驱动的一部分，不是可选项。**

## 三、⭐ 转速公式推导

### 3.1 单位链条

```
counts_per_rev = lines × 4                       （4 倍频）
counts_per_sec = delta × (1000 / T)              （delta 是 T 毫秒内的计数）
rpm_motor      = counts_per_sec × 60 / counts_per_rev
rpm_out        = rpm_motor / 齿轮比
rpm10          = rpm_out × 10
```

### 3.2 整理成整数公式

```
设 gear_x10 = 齿轮比 × 10

rpm10 = delta × (1000/T) × 60 / (4 × lines) × 10 / (gear_x10/10) × 10
      = delta × 1000 × 60 × 100 / (T × 4 × lines × gear_x10)
      = delta × 6,000,000 / (4 × T × lines × gear_x10)
      = 【delta × 1,500,000 / (T × lines × gear_x10)】
```

### 3.3 预计算 `k` 减少运行时乘法

```c
s_k = 1500000 / ENCODER_SAMPLE_MS;             /* Init 里算一次 */
s_rpm10 = (delta * s_k) / (s_lines * s_gear_x10);
```

**⚠️ 必须"先乘完，最后一次性除"** —— 连续整除会每次都截断：

```c
/* ❌ 每除一次截断一次 */
rpm10 = delta * 1500000 / T / lines / gear_x10;

/* ✅ 先乘后除 */
rpm10 = delta * k / (lines * gear_x10);
```

### 3.4 ⚠️ `gear_x10` 的约定（**容易错**）

| 减速比 | `gear_x10` |
|---|---|
| **1:1（无减速）** | **10** ← 不是 1！ |
| 1:10 | **100** |
| 1:7.5 | **75** |

**⭐ 因为公式里是"除以 gear_x10"，传 1 会把速度放大 10 倍。**

### 3.5 数值校验

| 场景 | `delta` | `T` | `lines` | `gear_x10` | `rpm10` | 校验 |
|---|---|---|---|---|---|---|
| EC11 手转 | 4 | 1000 | 20 | 10 | **30**（3.0 rpm）| 4 计数/秒 × 60 / 80 = 3 rpm ✅ |
| EC11 快转 | 20 | 1000 | 20 | 10 | **150**（15 rpm）| 20 × 60 / 80 = 15 rpm ✅ |
| 电机 3000rpm | 2000 | 10 | 1000 | 10 | **30000**（3000 rpm）| 200000 × 60 / 4000 = 3000 rpm ✅ |

## 四、⭐ 为什么对外返回 `rpm × 10` 而不是整数 rpm

**整数 rpm 在低速会丢成 0：**

```
编码器 4000 计数/圈，采样 10ms
counts/s = N × 100
rpm = N × 100 × 60 / 4000 = N × 1.5

N = 1  →  1.5 rpm  →  整数截断成 【1】（误差 33%）
N = 0  →  0 rpm
```

**⭐ 低速时整数 rpm 的分辨率只有 1.5 rpm，截断直接吃掉一半精度。**

**修法：对外返回 `rpm × 10`（单位 0.1 rpm）** —— **整数运算要保持精度，就在单位上放大。**

**⭐ 这和 `g_speed_dps` 乘 10、`gear_x10` 乘 10 是同一个思路。**

## 五、溢出与异常保护

```c
int16_t delta = (int16_t)(now - s_last_cnt);    /* 有符号差值处理 16 位回绕 */
```

**为什么加阈值**：

```
delta 正常范围：
  电机 3000rpm、4000 计数/圈、10ms → delta = 2000
  超过阈值说明：干扰 / CNT 回绕了两次 / 初始化没调
```

### ⭐ 阈值必须**按 `k` 反算**，不能拍脑袋

```
int32 上限 = 2,147,483,647
k = 1,500,000 / T

T = 10ms   → k = 150000  → 最大安全 delta = 2147483647 / 150000 = 【14316】
T = 100ms  → k = 15000   → 最大安全 delta = 【143165】
T = 1000ms → k = 1500    → 最大安全 delta = 【1431655】（超过 int16 上限，实际无限制）
```

**⚠️ 常见错误：写死 20000**

```
20000 × 150000 = 3,000,000,000  >  2,147,483,647  ❌ 已经溢出了
```

**正确做法：在 `ENCODER_Init` 里按 `k` 算出阈值**

```c
static int32_t s_delta_max = 0;

/* Init 里 */
s_delta_max = (int32_t)(2000000000L / s_k);     /* 留 7% 余量 */

/* Update 里 */
if (delta > s_delta_max || delta < -s_delta_max) return;
```

| `ENCODER_SAMPLE_MS` | `k` | `s_delta_max` | 对 `int16_t delta` 的实际约束 |
|---|---|---|---|
| **10** | 150000 | **13333** | ✅ 有效 |
| 100 | 15000 | 133333 | 无约束（delta 最大 32768）|
| 1000 | 1500 | 1333333 | 无约束 |

**⭐ 关键认识：阈值只在 `T` 小（`k` 大）时才有意义** —— **`T=10ms` 时 `delta` 超过 13333 就会乘法溢出。**

**⭐ 真实场景下不会超**（10000 rpm + 4000 计数/圈 + 10ms → delta = 6666），**但阈值是"防御性编程"，不能省。**

## 六、实测验证

### 6.1 位置验证

```
转 20 格  →  ENCODER_GetPosition() = 80
```

**20 格 × 4 倍频 = 80** ✅ **确认 `lines=20` 不是 10 或 40。**

### 6.2 节拍精度（5 秒内 `dbg_update_cnt` 增量）

| 预期 | 实测 | 偏差 |
|---|---|---|
| **500** | **499** | **−0.2%** |

**平均周期 = 5s / 499 = 10.02 ms** —— 定时器分辨率内 ✅

### 6.3 转速量级（临时把采样周期改成 1000ms）

| 手转速度 | 预期 `rpm10` | 实测 | 偏差 |
|---|---|---|---|
| **1 格/秒** | 30 | **28** | −6.7% |
| **5 格/秒** | 150 | **157** | +4.7% |

**⭐ 偏差来自"人手计时不准"**：

```
rpm10 = 28 → 0.93 格/秒（你要的是 1 格/秒，实际用了 10.7 秒转 10 格）
人手在 10 秒内的计时误差 ±0.5 秒 = ±5% → 与实测偏差吻合
```

**⭐ 公式验证通过；偏差不是代码误差。**

### 6.4 想要精确验证：用方波代替手转

```
TIM2_CH1 (PA0) ── PA6（编码器 A 相）
PA7 ── 悬空（内部上拉恒高，无额外边沿）

TIM2 输出 100 Hz → 每秒 200 个边沿 → 200 计数/秒
rpm10 = 200 × 7.5 = 【1500】（150.0 rpm），应该是精确值
```

**⭐ 手转验证"量级"，方波验证"精度"** —— 两种手段互补。

## 七、⚠️ 用 EC11 验证 10ms 采样驱动的局限

### 7.1 问题

```
EC11：每圈 80 计数
手转速度：约 1 格/秒 = 4 计数/秒
采样周期：10ms

每 10ms 的 delta = 4 × 0.01 = 0.04 个计数
→ 绝大多数窗口 delta = 0
→ 偶尔某个窗口 delta = 1

delta = 1 时：rpm10 = 750（75.0 rpm）
真实平均转速：4 计数/秒 = 3 rpm
→ 【高估 25 倍】，读数在 0 和 75 之间乱跳
```

**⭐ 这不是驱动的 bug** —— **驱动是给电机设计的**（4000 计数/圈、3000 rpm 时每 10ms 有 2000 个计数，绰绰有余）。

**⭐ 这是"采样周期必须匹配信号速率"的必然结果** —— 和 Day 4 实验 C（13Hz 时 M 法读 10）是同一个问题。

### 7.2 验证驱动时的对策：临时放长采样周期

**测 EC11 时把 `ENCODER_SAMPLE_MS` 改成 1000（1 秒）**：

```c
#define ENCODER_SAMPLE_MS   1000
TIMER_Setup(TIM4, 100, 1000000);        /* ⚠️ tick 必须加大，1000000/2 超 16 位 */
```

**为什么 tick 要改成 100**：

```
TIMER_Setup(TIM4, 2, 1000000) → period/tick = 500000 > 0xFFFF  → 返回 -1
TIMER_Setup(TIM4, 100, 1000000) → period/tick = 10000 ✅ → ARR = 9999
```

**改完后的映射**：

```
s_k = 1,500,000 / 1000 = 1500
rpm10 = delta × 1500 / (20 × 10) = delta × 7.5

1 格/秒 → delta=4  → rpm10 = 30（3.0 rpm）✅
5 格/秒 → delta=20 → rpm10 = 150（15 rpm）✅
```

**⭐ 验完必须改回 10ms。**

### 7.3 调试观察技巧（只改 main.c，不动驱动）

```c
volatile int32_t dbg_rpm10_last = 0;

while (1)
{
    dbg_rpm10 = ENCODER_GetRpm10();
    if (dbg_rpm10 != 0) dbg_rpm10_last = dbg_rpm10;   /* 保留最近非零值 */
}
```

**⚠️ 这只是调试手段，正式产品里速度必须真实反映"当前为 0"** —— 否则 PID 会以为电机还在转。

## 八、踩坑记录

### 坑 1：Keil Watch 显示 `<cannot evaluate>` + `Type: uchar`

**现象**：`s_position` 看不到，类型显示 `uchar`（实际是 `int32_t`）。

**原因**：
1. **调试会话是旧的**（`.axf` 重建了但没重进调试）
2. **`s_position` 是 `static`**（作用域限于 `encoder.c`）
3. **优化等级高**（`-O2/-O3` 可能优化掉 `static` 变量）

**修法**：

| 步骤 | 操作 |
|---|---|
| **1** | `Options → C/C++ → Optimization = Level 0 (-O0)` |
| **2** | `Options → Output → 勾上 Debug Information` |
| **3** | **Rebuild all**（不是 Build） |
| **4** | 重新进调试，**暂停**后看 |
| **5** | 用**全局影子变量**（最可靠）：`volatile int32_t dbg_pos = ENCODER_GetPosition();` |

**⭐ `Type: uchar` 是"找不到符号"的信号** —— Keil 在猜类型。**看到这个就该 Rebuild，不要怀疑代码。**

### 坑 2：`ENCODER_GetPosition` 放 Watch 显示 `<cannot evaluate>`

**原因**：**Watch 只能监视变量，不能监视函数。**

**⭐ 函数没有"值"** —— 就像问"`main` 的值是多少"。

**修法**：用影子变量接住返回值。

### 坑 3：中文乱码（新建工程必现）

**根因**：**源文件是 UTF-8，Keil 编辑器默认用 ANSI（GB2312）打开。**

```
UTF-8 的 3 字节汉字 → 被当成 1.5 个 GB2312 汉字 → 乱码
在 Keil 里保存 → 转成 GB2312 → 文件被"污染"
```

**修法（推荐）**：**所有 `.c/.h` 存成 UTF-8 with BOM**

**BOM = `EF BB BF`** —— **Keil 看到 BOM 就强制用 UTF-8 打开，不管全局设置。**

**⭐ 修好 `_模板` 才能根治"新建工程必乱码"。**

### 坑 4：采样周期与信号速率不匹配

见第七节。**⭐ 驱动本身没错，是"测试载体不适合"** —— 用 EC11 验 10ms 驱动的转速，物理上就测不准。

## 十一、结论

1. **驱动不占用节拍定时器** —— 由应用层调用 `ENCODER_Update()`，实现依赖倒置。
2. **`ENCODER_Update()` 必须在 ISR 里调用** —— 保证 `dt` 严格固定。
3. **转速公式：`rpm10 = delta × 1,500,000 / (T × lines × gear_x10)`**。
4. **必须"先乘后除"** —— 连续整除会每次截断。
5. **`gear_x10` 的 1:1 是 10，不是 1** —— 否则速度放大 10 倍。
6. **对外返回 0.1 rpm** —— 整数 rpm 在低速丢精度。
7. **参数检查是驱动的一部分** —— 包括 `k` 能否整除。
8. **`delta` 阈值必须按 `k` 反算**（`2e9 / k`），**写死数字会溢出**。
9. **⭐ 采样周期必须匹配信号速率** —— 用 EC11 验 10ms 驱动测不准，是物理限制不是代码 bug。
10. **⭐ `<cannot evaluate>` + `uchar` = 符号表问题** → `-O0` + Rebuild + 全局影子变量。
