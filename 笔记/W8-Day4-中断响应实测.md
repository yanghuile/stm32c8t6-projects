# W8 Day4 —— 中断响应时间实测

> 目标：用逻辑分析仪 + DWT 周期计数器，量出中断响应和 ISR 执行的真实时间，
> 并验证「ISR 太长会拖慢主循环」这个说法。

---

## 一、测量方法

### 1.1 为什么不能用按键当触发源

| 问题 | 说明 |
|---|---|
| 抖动 | 按键按下瞬间有 1~5ms 触点抖动，第一个边沿的时刻不确定 → 测出的"延迟"没有意义 |
| 人手误差 | 你按下的时刻本身就有 ±10ms 抖动 |

正确做法：用 GPIO 产生软件控制的干净边沿。

```
PA0（推挽输出，主循环控制）
  │  杜邦线短接
  ▼
PA1（上拉输入，配 EXTI1 下降沿触发）
  │
  ▼
EXTI1_IRQHandler 里 gpio_set/gpio_reset(PA12) 打点
```

PA0 的边沿时刻精确到指令周期 —— 这才是可靠的触发源。

### 1.2 接线

| 信号 | 板子引脚 | 逻辑分析仪 |
|---|---|---|
| 触发信号 | PA0 | D0 |
| ISR 打点 | PA12 | D1 |
| 地 | GND | GND（必须共地） |

另外：PA0 用杜邦线短接到 PA1。

### 1.3 两种时间测量手段

| 手段 | 精度 | 测什么 |
|---|---|---|
| 逻辑分析仪（24MHz，41.7ns/点） | ±42 ns | ISR 脉冲宽度、中断延迟 |
| DWT 周期计数器（Cortex-M3 内置） | 13.9 ns（1 个周期） | ISR 内部的 CPU 周期数 |

两者独立，可以交叉验证。

## 二、代码关键部分

### 2.1 DWT 周期计数器（寄存器定义）

```c
#define CoreDebug_DEMCR  (*(volatile uint32_t *)0xE000EDFCUL)
#define DWT_CTRL         (*(volatile uint32_t *)0xE0001000UL)
#define DWT_CYCCNT       (*(volatile uint32_t *)0xE0001004UL)
```

初始化（main 里，配完中断后）：

```c
CoreDebug_DEMCR |= (1UL << 24);   /* TRCENA：使能调试跟踪 */
DWT_CYCCNT = 0;
DWT_CTRL  |= 1UL;                 /* CYCCNTENA：启动周期计数器 */
```

### 2.2 EXTI1 配置（PA1）

```c
RCC->APB2ENR |= RCC_APB2ENR_IOPAEN | RCC_APB2ENR_AFIOEN;

gpio_set(GPIOA, 1);                                /* 先定上拉方向 */
gpio_config(GPIOA, 1, GPIO_CFG_IN_PULL);

AFIO->EXTICR[1 / 4] &= ~(0x0FUL << ((1 % 4) * 4)); /* EXTI1 ← PA */
AFIO->EXTICR[1 / 4] |=  (0x00UL << ((1 % 4) * 4));

EXTI->FTSR |=  (1UL << 1);                         /* 下降沿 */
EXTI->RTSR &= ~(1UL << 1);
EXTI->IMR  |=  (1UL << 1);

NVIC_IPR[IRQ_EXTI1] = (uint8_t)(0 << 4);           /* 最高优先级 */
NVIC_ISER0 = (1UL << IRQ_EXTI1);
```

### 2.3 ISR（★ 脉冲式打点，这是关键）

```c
volatile uint32_t g_isr_cycles = 0;
volatile uint32_t g_isr_count  = 0;

void EXTI1_IRQHandler(void)
{
    uint32_t t0 = DWT_CYCCNT;

    gpio_set(GPIOA, MARK_PIN);              /* ★ 进 ISR 立刻置高 → 脉冲起点 */

    if (EXTI->PR & (1UL << IN_PIN))
    {
        EXTI->PR = (1UL << IN_PIN);         /* 清挂起标志 */

        for (volatile uint32_t i = 0; i < 10000; i++) { }   /* 实验变量 */

        g_isr_count++;
    }

    gpio_reset(GPIOA, MARK_PIN);            /* ★ 出 ISR 拉低 → 脉冲终点 */
    g_isr_cycles = DWT_CYCCNT - t0;         /* 周期数（比脉冲宽度多两头的指令） */
}
```

### 2.4 波形解读

```
CH0 (PA0)  ‾‾‾‾|___________________|‾‾‾‾‾‾‾
               ↑ 触发（覆盖下降沿）
               │
CH1 (PA12) _____|‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾|______
              ↑                    ↑
              └ CH1 高电平宽度 = ISR 执行时间
```

| 要测的量 | 看哪里 |
|---|---|
| 中断延迟 | CH0↓ → CH1↑ 的间隔（很窄，24MHz 下约 1 个像素） |
| ISR 执行时间 | CH1 高电平宽度（这是本实验的主测量对象） |

## 三、实测数据

### 3.1 三组实验

| 实验 | ISR 里的空循环 | DWT 周期数 | 折算时间 | 逻辑分析仪（光标） |
|---|---|---|---|---|
| 基准 | 无 | 87（0x57） | 1.208 μs | 0.79 μs |
| 实验 2 | 1000 次 | 12 099（0x2F43） | 168.04 μs | 166.1 μs |
| 实验 3 | 10000 次 | 120 098（0x1D522） | 1 668.03 μs | 1 668.2 μs |

换算公式：`时间(ns) = 周期数 × 1000 / 72 = 周期数 × 13.889`

### 3.2 交叉验证

| 实验 | 逻辑分析仪 | DWT − 固定指令开销 | 偏差 |
|---|---|---|---|
| 基准 | 0.79 μs | 1.208 − 0.42 = 0.788 μs | 0.3% |
| 实验 2 | 166.1 μs | 168.04 − 0.42 = 167.62 μs| 0.9% |
| 实验 3 | 1 668.2 μs | 1 668.03 − 0.42 = 1 667.61 μs | 0.04% |

为什么 DWT 比脉冲宽度大 0.42 μs（约 30 周期）：

```c
uint32_t t0 = DWT_CYCCNT;     ← 计时开始，但 CH1 还没变
gpio_set(GPIOA, MARK_PIN);    ← 脉冲起点
...
gpio_reset(GPIOA, MARK_PIN);  ← 脉冲终点
g_isr_cycles = DWT_CYCCNT - t0;   ← 计时结束，但 CH1 已经变了
```

两头的指令（读 DWT、写 BSRR、最后再读 DWT）都在 `g_isr_cycles` 里，但不在脉冲宽度里
→ 所以 `g_isr_cycles × 13.9ns − 0.42μs ≈ 脉冲宽度`。

两种独立方法误差都小于 1%，说明测量结果可信。

### 3.3 单次空循环的成本

```
实验 2 ：(12 099 − 87) / 1000  = 12.012 周期/次 = 166.8 ns
实验 3 ：(120 098 − 87) / 10000 = 12.001 周期/次 = 166.7 ns
```

1000 次和 10000 次两次独立测量相差 0.09% —— 说明这个数字非常可靠。

为什么是 12 周期：`volatile` 禁止编译器把 `i` 缓存在寄存器里，
每次迭代都要真实执行「读内存 → 比较 → 分支 → 加一 → 写内存 → 跳回」，
约 8~12 个周期。去掉 `volatile` 后编译器会优化掉整个循环 —— 这正好反证了它的成本来自内存访问。

## 四、结论

### 4.1 中断响应在 μs 量级

```
引脚电平变化 → ISR 第一行代码执行完：约 1.2 μs（87 周期）
```

| 对比对象 | 延迟 | 倍数 |
|---|---|---|
| 中断** | ≈ 1.2 μs | 1× |
| 轮询（即使做到 100 μs 周期） | 100 μs（最坏情况） | 83× |
| `KEY_Scan()` 阻塞式轮询 | 20 000 μs（20ms） | 16 667× |

这就是中断存在的理由：不是"更优雅"，是"快两个数量级"。

### 4.2 ISR 的耗时几乎全在代码，不在硬件

| 组成 | 时长 | 占比（基准实验） |
|---|---|---|
| 硬件开销（压栈 8 寄存器 + 取向量 + 出栈） | 约 0.17~0.28 μs（12~20 周期） | 15~23% |
| ISR 代码本身 | 约 0.9 μs | 77~85% |

所以"ISR 要短"的意思很明确：硬件开销是固定的，能优化的只有你写的代码。

### 4.3 ISR 变长会等比例拖慢主循环（本实验最重要的结论）

主循环结构：`gpio_reset(PA0) → Delay_ms(1) → gpio_set(PA0)`

PA0 拉低后立刻触发 EXTI，ISR 在 `Delay_ms(1)` 期间执行，把延时撑长：

| 实验 | ISR 时长 | `Delay_ms(1)` 实际耗时 | 超时 |
|---|---|---|---|
| 基准 | 1.2 μs | ≈ 1.001 ms | +0.1% |
| 实验 2 | 168 μs | ≈ 1.168 ms | +16.8% |
| 实验 3 | 1 668 μs | ≈ 2.668 ms | +166.8% |

CH0 的低电平宽度直接反映了这一点：实验 3 时 CH0 的低电平从 1ms 被拉到约 2.67ms。

推论：

| 场景 | ISR 里允许做的事 |
|---|---|
| 1ms 控制周期 | ISR 必须 < 50 μs（留 5% 预算） |
| 100 μs 控制周期 | ISR 必须 < 5 μs |
| 只做标志位 + 清中断 | < 1 μs（推荐） |

耗时工作（计算、打印、协议解析）一律交给主循环或任务。

## 五、踩坑记录

### 坑 1：用 `gpio_toggle` 打点，量出过假数据

最初 ISR 里用 `gpio_toggle(PA12)`：

```
周期 N   ：CH0↓  +  CH1 高→低
周期 N+1 ：CH0↓  +  CH1 低→高
```

CH1 每个周期翻转一次，相邻周期的边沿方向相反→
很容易把「本周期的 CH0↓」和「上周期的 CH1 边沿」对上，
量出过 4.8 μs的假延迟（真实值约 1 μs）。

修正：改成"进 ISR 置高、出 ISR 拉低"的脉冲式打点 ——
延迟和 ISR 时长在同一个波形上清晰分开，也不再有方向歧义。

### 坑 2：空循环放在打点之后，测不到它的成本

最初代码：

```c
gpio_toggle(MARK_PIN);        /* 打点在前 */
for (...) { }                 /* 空循环在后 */
```

这样「CH0↓ → CH1 变化」这个量根本不含空循环 ——
空循环发生在打点之后，测出来的延迟永远是 ~1 μs。

修正：用脉冲宽度（进 ISR 置高、出 ISR 拉低）来测 ISR 总时长，
空循环的效果就完整体现在脉冲宽度里。

教训：测什么，打点就要把被测对象包在中间。

### 坑 3：24MHz 采样测不了 ns 级延迟

24MHz = 41.7ns/点，而中断延迟约 167ns ≈ 4 个采样点。

在能看清单个采样点的缩放下，延迟只占几个像素，光标对不准。

结论：24MHz 逻辑分析仪适合测 μs 级（ISR 时长），不适合测 ns 级（硬件延迟）。
要精确测延迟，需要 ≥ 200MHz 的示波器，或用定时器输入捕获打时间戳（W10 会学）。

## 六、局限与改进方向

| 局限 | 原因 | 改进 |
|---|---|---|
| 延迟只能定性（< 0.2 μs） | 24MHz 采样分辨率不足 | 定时器输入捕获 + 72MHz 计数（精度 13.9ns） |
| 没测「不同优先级中断的抢占开销」 | 需要两个中断源 | W8 Day5/6 加第二个 EXTI 或定时器中断 |
| 没测「中断嵌套深度」对栈的影响 | 需要观察 SP | W17 RTOS 阶段会涉及 |
| DWT 计数器需要调试器不断电 | `CoreDebug_DEMCR` 在某些复位后会被清 | 生产代码不依赖 DWT |

---

## 七、可复用的结论

1. ISR 只做三件事：判断来源、清标志、置标志/最短动作。
2. 耗时工作一律出 ISR —— 有量化依据（ISR 1.67ms → 主循环超时 167%）。
3. 测中断时序不要用按键，用 GPIO 对 GPIO。
4. 打点要包住被测对象：测总时长用「置高→拉低」，测响应用「触发→置高」。
5. 交叉验证：逻辑分析仪（μs 级）+ DWT（ns 级）互相印证，误差 < 1% 才可信。
