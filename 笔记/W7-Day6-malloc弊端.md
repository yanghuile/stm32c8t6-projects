# W7 Day6 —— 嵌入式为什么不用malloc
---

## 一、一句话解释碎片化
系统空闲内存被分割成大量不连续的小块，虽然空闲总容量充足，但无法分配出满足需求的连续内存。

## 二、说出至少两条"单片机不用 malloc"的理由
1. 容易产生内存碎片，长期反复 malloc/free 后，空闲内存被切成零散小块，后续申请大块内存失败。
2. 没有操作系统内存保护，malloc 失败返回 NULL。很多代码不检查就直接用 → 访问地址 0 附近（Flash 别名区，只读）→ 硬件异常 HardFault → 死机，且现场无法定位。
3. malloc的执行时间不确定。

## 三、总空闲 10240 B 为什么连 512 B 都分配不出来？
动态内存分配要求分配连续的内存空间。虽然空闲内存总和足够，但空闲区域被已占用内存隔开、碎片化，不存在一块大于等于 512B 的连续空闲块，因此分配失败。

## 四、栈溢出为什么不报错？ 它会踩坏什么？
栈溢出不会报错：单片机裸机无硬件内存保护，越界访问不会自动捕获。
栈溢出会踩坏：函数返回地址（造成程序跑飞）、全局变量、堆内存，引发 HardFault 死机。

## 五、static uint8_t buf[256]; 和 uint8_t buf[256];（在函数内）有什么区别？ 各自放在哪块内存？
函数内`static uint8_t buf[256]`：存储在静态存储区 (.bss)，上电分配，程序全程存在，仅初始化一次，调用退出后数组数据保留，不占用栈。
函数内`uint8_t buf[256]`：存储在栈 (Stack)，调用函数时分配，函数返回内存释放；每次调用数组内容随机，占用栈空间，数组太大容易栈溢出。

## 七、C8T6 的 RAM 有多大
| 项 | 大小 | 占 RAM 比例 |
|---|---|---|
| SRAM 总量 | 20 KB = 20480 B | 100% |
| `int buf[1000]` | 4000 B | 19.5% |
| `char buf[8192]` | 8192 B | 40% |
| `int mat[50][50]` | 10000 B | 48.8% |
| 栈（默认） | 约 1 KB | 5% |
