# W10 Day4 —— M 法 vs T 法对比实测

> 目标：在同一个信号上同时跑 M 法和 T 法，用实测数据说明"高速用 M、低速用 T"。
> 交付：三组对比数据（基准 / 粗捕获 / 低频），量化误差的数学解释。

---

## 一、两种测速方法的本质

| | **M 法**（Frequency Measurement）| **T 法**（Period Measurement）|
|---|---|---|
| **测什么** | 固定**时间窗口**内的**脉冲个数** | 固定**脉冲个数**的**时间间隔**|
| **量化单位** | **1 个脉冲** | **1 个计数（tick）**|
| **误差公式** | `1 / 窗口内脉冲数` | `1 个 tick / 周期` |
| **高速时** | ✅ 准（脉冲多） | ❌ 不准（周期小，1 tick 占比大）|
| **低速时** | ❌ 不准（脉冲少） | ✅ 准（周期长）|
| **响应速度** | 慢（等窗口结束） | 快（每个脉冲都能算）|
| **硬件** | 计数器（编码器模式） | 输入捕获 |

**⭐ 一句话**：**M 法用"长窗口"换"高频精度"，T 法用"细 tick"换"低频精度"。**

---

## 二、实验设计：一次配置，两种方法同时跑

### 2.1 核心洞察

**输入捕获的每一次中断，同时提供了两个信息：**

```
TIM3_CH1 输入捕获（PA6）
    │
    ├─ 读 CCR1 → 和上次差值 = 周期 → 【T 法】
    └─ cnt++   → 每 100ms 除以窗口 → 【M 法】
```

**同一个信号、同一份中断代码，两种方法并行计算** → **对照实验，没有额外变量。**

### 2.2 硬件连接

```
PA0（TIM2_CH1，信号源）── 杜邦线 ── PA6（TIM3_CH1，输入捕获）
PA5 ── 按键（切换测试档位）
```

**⭐ 不需要任何外部信号发生器** —— **MCU 自己产生方波，自己测。**

### 2.3 定时器分工

| 定时器 | 作用 | 配置 |
|---|---|---|
| **TIM2** | PWM 输出已知频率 | `TIMER_Setup(TIM2, 2, period_us)` |
| **TIM3** | 输入捕获（T 法 + M 法计数）| `TIMER_Setup(TIM3, 1, 0x10000)` |
| **TIM4** | 100ms 窗口节拍（M 法用）| `TIMER_Setup(TIM4, 2, 100000)` |

## 三、⭐ 基准实验：**四档全对，但证明不了差异**

### 3.1 数据

| 档位 | `g_true_freq` | `g_t_period` | `g_t_freq` | `g_m_freq` | 误差 |
|---|---|---|---|---|---|
| **10 Hz** | 10 | 100000 | **10** | **10** | 0 / 0 |
| **100 Hz** | 100 | 10000 | **100** | **100** | 0 / 0 |
| **1 kHz** | 1000 | 1000 | **1000** | **1000** | 0 / 0 |
| **10 kHz** | 10000 | 100 | **10000** | **10000** | 0 / 0 |

### 3.2 ⭐ 为什么全部精确 —— 这是实验设计的局限

**信号源和测量时钟是同一个 72MHz：**

```
TIM2（信号源）  ← 72MHz 分频
TIM3（T 法捕获）← 72MHz 分频
TIM4（M 法窗口）← 72MHz 分频
        ↑
   三个定时器同源
```

**所以所有周期都是"整数个计数"，没有任何量化误差：**

| 档位 | 信号周期 | 捕获 tick | 计数值 | 有量化误差吗 |
|---|---|---|---|---|
| 10 Hz | 100000 μs | 1 μs | **100000**（整数）| ❌ 无 |
| 10 kHz | 100 μs | 1 μs | **100**（整数）| ❌ 无 |
| 10 Hz（M 法） | 100 ms | 窗口 100 ms | **1.000 个** | ❌ 无 |

**⭐ 量化误差只在"计数值不是整数"时出现。自产自测时，一切都被设计成整数了。**

### 3.3 ⭐ 这个局限的现实意义

> **信号源和测量时钟同源时，量化误差被"整数倍关系"完全消除。**
> **这解释了为什么"实验室测得好好的，现场就不行"** ——
> **现场的信号源和你的测量时钟无关，小数点后的部分必然存在。**

### 3.4 怎么才能暴露差异：**打破整数倍关系**

| 要暴露 | 做法 | 结果 |
|---|---|---|
| **T 法误差** | 让"周期不是 tick 的整数倍"（加大 tick 或找特殊频率）| T 法读数在两个值之间跳 |
| **M 法误差** | 让"窗口内脉冲数不是整数"（用不整除窗口的频率）| M 法读数在两个值之间跳 |

## 四、实验 B：暴露 T 法误差（粗捕获 + 高频）

### 4.1 配置

```c
TIMER_Setup(TIM3, 256, 0x10000);      /* tick 从 1μs 加到 256μs */
```

**为什么必须用 2 的幂**：`0x10000 = 65536 = 2¹⁶`，**只能被 2 的幂整除**。

| `tick_us` | `65536 / tick_us` | `ARR` | 合法？ |
|---|---|---|---|
| 1 | 65536 | 65535 | ✅ |
| 16 | 4096 | 4095 | ✅ |
| **256** | **256** | **255** | ✅ ⭐ |
| 300 | 218.45 | — | ❌ **不能被 65536 整除** |

### 4.2 推演

```
信号周期 = 1000 μs，捕获 tick = 256 μs
ticks = 1000 / 256 = 3.906  ← 不是整数

硬件只能整数计数，每次捕获到：
  3 个 tick → 768  μs → g_t_freq = 1302 Hz  （+30.2%）
  4 个 tick → 1024 μs → g_t_freq =  976 Hz  （ -2.4%）
```

### 4.3 实测

| 变量 | 值 | 说明 |
|---|---|---|
| `g_true_freq` | **1000** | 信号源真实频率 |
| `g_t_period` | **1024** | 抓到"4 个 tick"那次 |
| `g_t_freq` | **976** | 1000000 / 1024 = 976.56 → 整数除法取 **976** |
| `g_m_freq` | **1000** | ✅ **稳定精确** |

**⭐ T 法误差 −2.4%（观测到的是靠近真值的那次）；多观察会看到 1302 出现（+30.2%）。**

**⭐ M 法在同一时刻读 1000，完全不受影响。**

## 五、实验 C：暴露 M 法误差（低频 + 不整除窗口）

### 5.1 配置

```c
static const uint32_t k_period_us[4] = { 76922, 10000, 1000, 100 };   /* 第一档 13 Hz */
TIMER_Setup(TIM3, 1, 0x10000);                                          /* tick 恢复 1μs */
```

### 5.2 推演

```
信号周期 = 76922 μs = 76.922 ms
M 法窗口 = 100 ms
窗口内脉冲数 = 100 / 76.922 = 1.30  ← 不是整数

M 法只能整数计数：
  读到 1 个 → g_m_freq = 10 Hz  （−23.1%）
  读到 2 个 → g_m_freq = 20 Hz  （+53.8%）
```

### 5.3 实测

| 变量 | 值 | 说明 |
|---|---|---|
| `g_true_freq` | **13** | 信号源真实频率 |
| `g_t_period` | **76922** | ✅ 精确（整数个 tick） |
| `g_t_freq` | **13** | ✅ 精确 |
| `g_m_freq` | **10** | ⭐ **真值 13，只能给到 10** |

**⭐ M 法误差 −23.1%；多观察会看到 20 出现（+53.8%）。**
**⭐ T 法在同一时刻读 13，完全精确。**

## 七、量化误差的数学

### 7.1 M 法

```
窗口 T_w 内，频率 f 的信号有 f × T_w 个脉冲
量化误差 = ±1 个脉冲
相对误差 ≈ 1 / (f × T_w)
```

### 7.2 T 法

```
信号周期 T = 1/f，计数频率 f_clk
一个周期内有 T × f_clk 个计数
量化误差 = ±1 个计数
相对误差 ≈ 1 / (T × f_clk) = f / f_clk
```

### 7.3 交叉点（两种方法误差相等）

```
1 / (f × T_w) = f / f_clk
→ f² = f_clk / T_w
→ f = √(f_clk / T_w)
```

**本项目参数**（`f_clk = 1MHz`，`T_w = 100ms`）：

```
f_cross = √(1,000,000 / 0.1) = √10⁷ ≈ 【3.16 kHz】
```

**⭐ 低于 3.16 kHz 用 T 法，高于用 M 法。**

### 7.4 参数怎么影响交叉点

| 改动 | 交叉点变化 | 结果 |
|---|---|---|
| **窗口 T_w 从 100ms → 1s** | `√(1e6/1) = 1000 Hz` | **交叉点降低**，M 法覆盖范围变大 |
| **计数频率从 1MHz → 72MHz** | `√(72e6/0.1) ≈ 26.8 kHz` | **交叉点大幅升高**，T 法覆盖范围变大 |

**⭐ 所以"精度"不是单一维度 —— 调参数就是在移动交叉点。**

## 八、工程结论

### 8.1 怎么选

| 场景 | 脉冲率 | 用哪种 |
|---|---|---|
| **步进电机 0~300 rpm**（低线数编码器）| 低频 | **T 法**（或 M/T 法）|
| **直流电机 3000~10000 rpm** | 中高频 | **M 法** |
| **工业伺服 0~3000 rpm 全范围** | 全范围 | **M/T 法** |

### 8.2 提高精度的三条路

| 方法 | 代价 |
|---|---|
| **T 法：提高计数频率**（PSC 调小）| 溢出更快 → 需要处理更多溢出 |
| **M 法：加长窗口** | 响应变慢 |
| **多周期平均**（T 法测 100 个周期再除 100）| 响应变慢，但误差降 100 倍 |

**⭐ 第三条就是"过采样"** —— **PID 的采样周期选择，本质就是"响应速度 vs 精度"的权衡。**

### 8.3 M/T 法（工业伺服的解法）

**思路**：**同时测"脉冲数"和"首尾脉冲的精确时间"**

```
在固定时间内数脉冲数 N
同时用捕获测"第 1 个脉冲"和"第 N+1 个脉冲"的精确间隔 T

速度 = N / T

→ N 大时（高速）：T 的量化误差影响小 → 相当于 M 法
→ N 小时（低速）：用 T 的精确时间来补偿 → 相当于 T 法
→ 【全范围内精度都好】
```

**⭐ 这就是"兼得两者优点"，也是为什么工业伺服能到 0.01% 精度。**

## 九、踩坑记录

### 坑 1：`TIMER_Setup(TIM3, 300, 0x10000)` 返回 -1

**原因**：`period_us % tick_us = 65536 % 300 = 136 ≠ 0` → **周期必须是 tick 的整数倍**。

**修正**：`0x10000 = 2¹⁶`，**tick 必须选 2 的幂**（1/2/4/8/16/32/64/128/256/512）。

### 坑 2：⭐ 配置失败 → `tick_us = 0` → **除零 HardFault**

```
TIMER_Setup 失败 → PSC 保持 0
→ tick_us = (PSC+1)/72 = 0
→ g_t_period = ticks × 0 = 0
→ g_t_freq = 1000000 / 0  →  【除零 → HardFault → 程序卡死】
```

**现象**：**所有数据冻结在 0，"T 法的数据没了"。**

**修正**：两处除零保护都要有

```c
if (ticks != 0 && tick_us != 0)
{
    uint32_t period_us = ticks * tick_us;
    if (period_us != 0)
    {
        g_t_period = period_us;
        g_t_freq   = 1000000UL / period_us;
    }
}
```

### 坑 3：⭐⭐ 三个"魔数"在配置变化后全部失效

```c
uint32_t delta = ovf_delta * 65536UL + (cap - last_cap);   /* 只对 ARR=0xFFFF */
g_t_period = delta;                                        /* 只对 tick=1μs */
g_t_freq   = 1000000UL / delta;                            /* 同上 */
```

**这三个写法在 `tick=1μs + ARR=0xFFFF` 时"恰好正确"** —— **一改配置就全崩。**

**修正：从寄存器反推，一个都不写死**

```c
uint32_t tick_us = (TIM3->PSC + 1) / 72;      /* 1 / 256 / ... */
uint32_t span    = TIM3->ARR + 1;             /* 65536 / 256 / ... */

uint32_t ticks = ovf_delta * span + (cap - last_cap);
uint32_t period_us = ticks * tick_us;
```

**⭐ 教训：能从寄存器反推的参数，绝对不要写成常量。**

### 坑 4：`timer.c` 的旧检查拒绝合法 tick

```c
if (72 % tick_us != 0) return -1;      /* ❌ 旧检查：只允许 72 的约数 */
if (tick_us > 910)     return -1;      /* ✅ 真约束：PSC ≤ 65535 */
```

**72 的约数只有 1/2/3/4/6/8/9/12/18/24/36/72** → **256 这样的"2 的幂"全被拒绝** → **无法做粗捕获实验。**

| # | 问题 | 答案 |
|---|---|---|
| **1** | 为什么基准实验四档全对？ | **信号源和测量时钟同源**，所有周期都是整数个计数，量化误差被"整数倍关系"消除 |
| **2** | 交叉点 3.16 kHz 怎么算？窗口改成 1s 后呢？ | `f = √(f_clk/T_w)`；1s 时 `√(1e6/1) = 1000 Hz` |
| **3** | 计数频率从 1MHz 提到 72MHz，交叉点？ | `√(72e6/0.1) ≈ 26.8 kHz` —— **交叉点大幅右移，T 法覆盖范围变大** |

## 十一、结论

1. **M 法量化单位是"1 个脉冲"，T 法量化单位是"1 个 tick"。**
2. **交叉点 `f = √(f_clk / T_w)`，本项目参数下 ≈ 3.16 kHz。**
3. **⭐ 自产自测无法暴露量化误差** —— 信号源和测量时钟同源时，一切都被整数倍关系"对齐"了。
4. **要暴露 T 法误差：加大 tick**（让周期不是 tick 的整数倍）。
5. **要暴露 M 法误差：用不整除窗口的频率**（让窗口内脉冲数不是整数）。
6. **实测：tick=256μs 时 T 法读 976（真值 1000，−2.4%）；13Hz 时 M 法读 10（真值 13，−23.1%）。**
7. **⭐ 三个"魔数"（65536、delta 当 μs、1e6/delta）在配置变化后全部失效** —— 必须从寄存器反推。
8. **配置失败会让 `tick_us = 0` → 除零 HardFault** → 除零保护要写两处。
9. **`0x10000 = 2¹⁶` 只能被 2 的幂整除** → 粗 tick 必须选 2 的幂。
10. **提高精度三条路：提高计数频率 / 加长窗口 / 多周期平均** —— 都是拿响应速度换精度。
