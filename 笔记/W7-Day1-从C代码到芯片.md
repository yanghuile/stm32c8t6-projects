从C代码到芯片

完整链路：
┌──────────────────────────────────────────────────────────────┐
│ ① 编译                                                       │
│    main.c  led.c  startup_stm32f10x_md.s                     │
│         ↓ armcc（ARM 编译器）                                 │
│    main.o  led.o  startup.o        ← 机器码 + 符号表          │
├──────────────────────────────────────────────────────────────┤
│ ② 链接                                                       │
│    *.o  +  库文件  +  启动文件                                │
│         ↓ armlink（按"分散加载文件"决定每段放哪个地址）         │
│    Project.axf                     ← ELF 格式（含调试信息）   │
├──────────────────────────────────────────────────────────────┤
│ ③ 转换                                                       │
│    Project.axf                                               │
│         ↓ fromelf --i32combined 或 --bin                     │
│    Project.hex  /  Project.bin      ← 纯烧录数据              │
├──────────────────────────────────────────────────────────────┤
│ ④ 烧录                                                       │
│    电脑 → USB → ST-Link → SWD(2线) → 芯片 Flash               │
│    【按 hex 里的地址，把数据写进 0x0800_0000 起的 Flash】       │
├──────────────────────────────────────────────────────────────┤
│ ⑤ 运行                                                       │
│    复位 → CPU 从 0x0000_0000 取栈顶、0x0000_0004 取复位向量    │
│    （BOOT0=0 时 0x0800_0000 被映射到 0x0000_0000）            │
│    → 跳到 Reset_Handler → 初始化 → main()                     │
└──────────────────────────────────────────────────────────────┘

Q1：完整链路
①编译：将C/汇编源代码翻译成obj目标文件，检查语法；单个文件翻译，此时各个文件之间的函数还没关联
②链接：把多个.obj目标文件+启动文件+库文件合并，解决函数、变量的地址引用，生成可执行的工程文件.axf。 确定全局变量、函数在单片机Flash里的存储地址
③转换：从.axf文件提取纯机器码，转换成十六进制文件.hex。 hex文件是可以给下载器识别的，去掉调试信息的固件
④烧录：使用下载器，把hex里的机器代码写入单片机的Flash程序存储器。单片机上电后，CPU从Flash读取指令执行，执行代码驱动GPIO点亮LED

Q2：.axf / .hex / .bin 的区别
.axf是ARM可执行文件，链接完成后直接生成；内容是机器码+符号表+行号、调试信息；作用是Keil在线Debug调试用，一般不用于量产烧录
.hex是ASCII文本格式；内容是机器码+对应的存储地址信息；作用是烧录固件，下载器根据里面的地址把代码写到单片机Flash
.bin是纯二进制机器码镜像；内容是原始代码\数据，不带任何地址信息；作用是直接按顺序写入存储器；烧录时必须手动指定起始烧录地址

Q3：三类内存：Flash、SRAM、外设寄存器分别存什么？哪个写入会触发动作而不是存储值？
Flash：    地址范围从0x0800 0000起，大小64KB，存储程序代码和常量
SRAM：     地址范围从0x2000 0000起，大小20KB，存储变量、栈、堆
外设寄存器：地址范围从0x4000 0000起，控制硬件
因此，写入外设寄存器会触发动作而不是存储值。可以知道外设寄存器的值会被硬件改变，所以必须用volatile

Q5：为什么烧录不等于加载到内存,程序烧进 Flash 后，变量在哪里？复位后又从哪取指令？
烧录是将固件写入Flash，只是保存程序；加载到SRAM是上电复位后，由启动代码完成的数据拷贝，烧录时不会拷贝，因此二者不等。程序烧入Flash 后：代码、常量存Flash；全局变量的初始值存Flash，上电后复制到SRAM；局部变量运行时放在SRAM栈。复位后CPU从 Flash 起始地址取指令执行。
