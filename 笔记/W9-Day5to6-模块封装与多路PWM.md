# W9 Day5~6 —— TIMER 驱动模块化 + 多路 PWM

> 目标：把定时器配置收进一个可复用模块；在同一工程里跑三路不同频率的 PWM，
> 并用「毫秒节拍 + 非阻塞查表」的结构让它们互不干扰。

---

## 一、为什么封装

### 1.1 封装前的 main.c

```c
TIM2->PSC = 71;
TIM2->ARR = 19999;
TIM2->CNT = 0;
TIM2->CCMR1 = (6UL << 4) | (1UL << 3);
TIM2->CCER  |= 1;
TIM2->CCR1   = 1500;
TIM2->EGR    = 1;
TIM2->SR     = (uint16_t)~1;
TIM2->CR1   |= (1UL << 7) | 1;
```

**问题**：

| # | 问题 |
|---|---|
| 1 | 换定时器（TIM2 → TIM3）要抄一遍 |
| 2 | 换通道（CH1 → CH2）要**重算 `CCMR1` 的位偏移**（4 → 12） |
| 3 | 换分辨率（1μs → 10μs）要重算 `PSC`、`ARR`、所有 `CCR` |
| 4 | 每个新工程都要再抄一遍 |

### 1.2 封装后

```c
TIMER_Setup(TIM2, 1, 20000);              /* 1μs/计数，20ms 周期 */
TIMER_PwmStart(TIM2, TIM_CH1, 1500);      /* CH1，脉宽 1500μs */
```

**12 行寄存器操作 → 2 行函数调用。**

## 二、接口设计

### 2.1 `timer.h`

```c
typedef enum
{
    TIM_CH1 = 1,
    TIM_CH2 = 2,
    TIM_CH3 = 3,
    TIM_CH4 = 4
} TimCh_t;

int  TIMER_Setup(TIM_TypeDef *tim, uint32_t tick_us, uint32_t period_us);
void TIMER_EnableUpdateIrq(TIM_TypeDef *tim, uint8_t prio);
void TIMER_PwmStart(TIM_TypeDef *tim, TimCh_t ch, uint32_t width_us);
void TIMER_PwmSetUs(TIM_TypeDef *tim, TimCh_t ch, uint32_t width_us);
void TIMER_Start(TIM_TypeDef *tim);
void TIMER_Stop(TIM_TypeDef *tim);
```

### 2.2 四个设计决策

| 决策 | 理由 |
|---|---|
| **参数用物理量**（`tick_us` / `period_us` / `width_us`），不用寄存器原值 | 调用方只说意图（"我要 20ms 周期"），**算数收进驱动** —— 不易漏 `-1` |
| **拆成 4 个函数**（Setup / PwmStart / EnableUpdateIrq / Start） | 每个函数只做一件事，**按需组合**：舵机只要 Setup+PwmStart，定时闪灯只要 Setup+EnableUpdateIrq |
| **GPIO 由调用方配**，驱动不碰 | 引脚选择是**硬件设计决策**，不属于定时器；若驱动内配，需要一张巨大的"定时器×通道×引脚×重映射"映射表 |
| **`TimCh_t` 从 1 开始** | 和 `CCR1`~`CCR4` 的编号一一对应，`ch - 1` 直接是数组/位运算下标 |

### 2.3 ⚠️ 驱动的"合同"

**`TIMER_PwmStart` 的注释必须写清**：

```c
/* ⚠️ 调用前必须把对应引脚配成复用推挽（GPIO_CFG_AF_PP_50MHZ）*/
void TIMER_PwmStart(TIM_TypeDef *tim, TimCh_t ch, uint32_t width_us);
```

**不写清 → 调用方漏配 GPIO → PWM 完全没输出**（本项目踩过，见第七节）。

## 三、实现要点

### 3.1 `TIMER_Setup`：4 道参数检查

```c
int TIMER_Setup(TIM_TypeDef *tim, uint32_t tick_us, uint32_t period_us)
{
    if (tick_us == 0)              return -1;   /* 挡住除零 */
    if (72 % tick_us != 0)         return -1;   /* tick 必须能整除 72 */
    if (period_us % tick_us != 0)  return -1;   /* 周期必须是 tick 的整数倍 */
    if (period_us / tick_us > 0x10000) return -1;  /* ARR 超 16 位 */

    /* 开时钟（TIM1 在 APB2，其余在 APB1）*/
    ...

    tim->PSC = 72 * tick_us - 1;
    tim->ARR = period_us / tick_us - 1;
    tim->CNT = 0;
    tim->EGR = 1;                    /* 载入影子寄存器 */
    tim->SR  = (uint16_t)~1;         /* UG 顺带置了 UIF，清掉 */
    return 0;
}
```

**⭐ 为什么第 2 道检查隐含了"PSC 不会溢出"**：

`tick_us` 必须整除 72 → `tick_us ≤ 72` → `PSC = 72 × tick_us − 1 ≤ 5183` → **永远在 16 位范围内**。

**所以不需要单独检查 PSC 溢出** —— **但要理解这个推导**，否则别人改检查条件时会破坏前提。

### 3.2 通道 → 寄存器的映射（最难的部分）

**4 个通道的配置分散在 3 个寄存器里**：

| 通道 | 模式寄存器 | 在寄存器内的位偏移 | `CCER` 位 | 比较寄存器 |
|---|---|---|---|---|
| **CH1** | `CCMR1` | **0** | bit0 | `CCR1` |
| **CH2** | `CCMR1` | **8** | bit4 | `CCR2` |
| **CH3** | `CCMR2` | **0** | bit8 | `CCR3` |
| **CH4** | `CCMR2` | **8** | bit12 | `CCR4` |

**推导规律（记住这两条就不用查表）**：

```
模式寄存器： ch ≤ 2 → CCMR1，否则 CCMR2
位偏移    ： 奇数通道（1/3）→ 0，偶数通道（2/4）→ 8
CCER 位   ： (ch - 1) × 4
```

**每个通道要写 3 个字段**：

| 字段 | 位置 | 值 |
|---|---|---|
| `OCxM[2:0]` | `偏移 + 4` | `110`（PWM 模式 1） |
| `OCxPE` | `偏移 + 3` | `1`（CCR 预装载） |
| `CCxE` | `CCER` 的 `(ch-1)×4` | `1` |

**⚠️ `CCR1`~`CCR4` 是 4 个独立寄存器，不是数组** —— 只能 `switch(ch)` 分别访问。**这是唯一"优雅不了"的地方。**

### 3.3 IRQ 号是算出来的

| 定时器 | IRQ 号 | 向量名 |
|---|---|---|
| **TIM1** | **25** | `TIM1_UP_IRQHandler` |
| TIM2 | 28 | `TIM2_IRQHandler` |
| TIM3 | 29 | `TIM3_IRQHandler` |
| TIM4 | 30 | `TIM4_IRQHandler` |

**⚠️ TIM1 不连续（25 而不是 27）** —— 因为它是高级定时器，有 **UP / CC / TRIG / BRK 四个中断**，占了 25~28 附近的位置，所以 TIM2 只能排在 28。

**用 `if-else` 链从指针反查**（比指针运算安全，不依赖地址布局）：

```c
if      (tim == TIM1) irq = 25;
else if (tim == TIM2) irq = 28;
else if (tim == TIM3) irq = 29;
else if (tim == TIM4) irq = 30;
else return;
```

### 3.4 清标志：`SR = (uint16_t)~1`

**`TIM->SR` 是 W0C（写 0 清）**：

```c
tim->SR = (uint16_t)~1;        /* ✅ 一条 STR，原子 */
tim->SR &= ~(1UL << 0);        /* ❌ 读-改-写，有竞态 */
```

**竞态推演**：

```
t0：LDR 读到 SR = 0x0001（只有 UIF）
t1：【硬件把 CC1IF 置 1】→ SR 实际变成 0x0003
t2：STR 写回 0x0000（写的是旧值）→ 【CC1IF 也被清掉】→ 丢失一次捕获中断
```

**为什么 `= ~1` 安全**：`SR` 的所有标志位都是 `rc_w0`，**写 1 无影响，写 0 才清** → 只有 bit0 被清。

### 3.5 `NVIC_ISER0 |=`（**注意这里必须用 `|=`**）

```c
NVIC_ISER0 |= (1UL << irq);      /* ✅ 正确 */
NVIC_ISER0  = (1UL << irq);      /* ❌ 会关掉之前使能的其他中断 */
```

**因为 `ISER` 是"写 1 置位、写 0 无影响"的寄存器**：读回的值里已使能的位是 1，`|=` 后写回仍是 1 → 不影响其他中断。

**⚠️ 这和其他"清标志用直接赋值"的规则相反** —— **关键看寄存器语义**：

| 寄存器 | 语义 | 写法 |
|---|---|---|
| `TIM->SR` | W0C | `= ~mask` |
| `EXTI->PR` | W1C | `= mask` |
| `NVIC_ISER` | 写 1 置位（读回 1） | `\|= mask` |
| `TIM->DIER` / `CCER` / `CR1` | 普通可读写 | `\|= mask` |

## 四、⭐ 零状态设计：`tick_of` 从 PSC 反推

### 4.1 问题

`TIMER_PwmSetUs(tim, ch, width_us)` 要把**微秒**转成**计数值**：

```c
ccr = width_us / (1 个计数 = 多少微秒)
```

**驱动怎么知道这个"多少微秒"？**

### 4.2 笨办法：存状态（**不要用**）

```c
static uint32_t s_tick_us[3];      /* 每个定时器一份 */
```

**问题**：

| # | 问题 |
|---|---|
| 1 | **多一份状态，就多一个"不同步"的机会** |
| 2 | 需要"定时器指针 → 数组下标"的映射 |
| 3 | 若写成单个全局变量 `g_tick_us`，**两个定时器不同分辨率时会互相覆盖** |

**⚠️ 这个坑真实发生过**：

```c
TIMER_Setup(TIM2, 1,  20000);    /* g_tick_us = 1  */
TIMER_Setup(TIM3, 10, 200000);   /* g_tick_us = 10 ← 覆盖了！*/
TIMER_PwmSetUs(TIM2, TIM_CH1, 1500);
/* 内部算 1500/10 = 150 → 实际只有 150μs，不是 1500μs ❌ */
```

### 4.3 妙办法：从寄存器反推（**零状态**）

```c
/* timer.c 内部工具函数（static，不放头文件）*/
static uint32_t tick_of(TIM_TypeDef *tim)
{
    return (tim->PSC + 1) / 72;
}
```

**为什么一定对**：

```
TIMER_Setup 里：PSC = 72 × tick_us − 1
所以：        (PSC + 1) / 72 = (72 × tick_us) / 72 = tick_us   ✔ 恒等
```

| PSC | `(PSC+1)/72` | tick_us |
|---|---|---|
| 71 | 72/72 = 1 | 1 μs |
| 719 | 720/72 = 10 | 10 μs |
| 35 | 36/72 = **0** | ⚠️ **除零风险** |

**⚠️ 隐患**：`PSC < 71`（比如没调过 `TIMER_Setup`，`PSC = 0`）时返回 0 → `width_us / 0` → **除零 → UsageFault → HardFault**。

**兜底**：

```c
uint32_t t = (tim->PSC + 1) / 72;
return (t == 0) ? 1 : t;
```

**⭐ 一句话总结这条设计原则**：

> **能从寄存器反推的参数，不要再存一份。**
> 两份数据必然不同步 —— 和"`angle = 0` 但 `CCR1 = 1500`"是同一类错误。

## 五、多路 PWM 工程结构

### 5.1 四路配置一览

| 定时器 | 通道 | 引脚 | 用途 | `tick_us` | `period_us` | 频率 |
|---|---|---|---|---|---|---|
| **TIM2** | CH1 | **PA0** | 舵机 | 1 | 20000 | **50 Hz** |
| **TIM3** | CH2 | **PA7** | 呼吸灯 | 1 | 100 | **10 kHz** |
| **TIM1** | CH1 | **PA8** | 直流电机（TB6612） | 1 | 50 | **20 kHz** |
| **TIM4** | — | 无 | **1 ms 节拍中断** | 1 | 1000 | 1 kHz |

**其他引脚**：PA5 按键、PB0/PB1 = 电机方向（AIN1/AIN2）、PB15 LED（错误提示）。

### 5.2 ⭐ 为什么必须用三个定时器

**`ARR` 是「定时器级」共享的** —— 同一个定时器的所有通道**必须共用同一个周期**，只有 `CCR` 不同（占空比不同）。

**所以你三路频率不同 → 必须三个不同的定时器。** ✅

| 想说 | 能不能 |
|---|---|
| TIM2_CH1 输出 50Hz，TIM2_CH2 输出 1kHz | ❌ **不可能**（ARR 共享） |
| TIM2_CH1 输出 50Hz 占空比 5%，TIM2_CH2 输出 50Hz 占空比 80% | ✅ 可以（只改 CCR） |

### 5.3 电机用 20 kHz 而不是 1 kHz

| PWM 频率 | 现象 |
|---|---|
| 1 kHz | **电机线圈啸叫**（1 kHz 在人耳最敏感频段） |
| **20 kHz** | 超出听觉范围，安静 |

**TB6612 支持到 100 kHz**，20 kHz 很安全。

**⚠️ 但 LED 用 10 kHz 甚至 1 kHz 都没事** —— **LED 是纯电子器件**，不像电机那样会"听到"电磁力脉动并振动发声。

## 六、⭐ 非阻塞多任务：`g_ms` 节拍模式

### 6.1 问题

**最初的写法**（`5.定时器` 早期版本）：

```c
while (1)
{
    for (duty = 0; duty <= 99; duty++)
    {
        TIMER_PwmSetUs(TIM3, TIM_CH2, duty);
        Delay_ms(10);                 /* ← 累计阻塞 2 秒 */
    }
}
```

**后果**：主循环 2 秒才轮一次 → **按键根本检测不到**。

### 6.2 解法：TIM4 只做「毫秒计数」

```c
static volatile uint32_t g_ms = 0;

void TIM4_IRQHandler(void)
{
    if (TIM4->SR & 1) { TIM4->SR = (uint16_t)~1; g_ms++; }
}
```

**ISR 只有 1 条语句（`g_ms++`），约 5 个 CPU 周期。**

**主循环里，每个任务自己查表**：

```c
while (1)
{
    /* ① 舵机：按键触发（不定时）*/
    if (KEY_Scan() == 1) { /* 改角度 */ }

    /* ② 呼吸灯：10ms 一拍 */
    if (g_ms - last_breathe >= 10)
    {
        last_breathe += 10;
        if (g_ms - last_breathe >= 10) last_breathe = g_ms;
        /* 呼吸步进 */
    }

    /* ③ 电机：2000ms 一拍 */
    if (g_ms - last_motor >= 2000)
    {
        last_motor += 2000;
        if (g_ms - last_motor >= 2000) last_motor = g_ms;
        /* 变速 */
    }
}
```

### 6.3 三条必须记住的规则

| # | 规则 | 为什么 |
|---|---|---|
| **1** | **阈值和步进必须同单位** | 条件写 `>= 10`，步进就得 `+= 10`；写 `>= 1` 就得 `+= 1` |
| **2** | **用减法比较，不用 `==`** | 主循环可能错过某个时刻，`==` 会永远等不到 |
| **3** | **`last += 周期`，不是 `last = g_ms`** | 前者在**固定网格**上推进（长期精确）；后者"走到哪算哪"（有漂移） |

**规则 3 的推演**（主循环节奏 7ms / 13ms 交替）：

```
用 last += 10：
  t=33 触发，last=30（网格点）→ 下次在 t=40 → 间隔 7ms
  t=47 检查，40-30=10 ✅ 触发，last=40
  长期平均 = 精确 10ms ✅

用 last = g_ms：
  t=33 触发，last=33
  t=40 检查，40-33=7 < 10 → 不触发
  t=53 检查，53-33=20 ✅ 触发，last=53
  间隔变成 20ms → 长期变慢 ❌
```

**规则 1 的坑真实发生过**：

```c
if (g_ms - last_breathe >= 10)     /* 10ms */
{
    last_breathe += 1;             /* ❌ 只推进 1ms → 每圈都触发 */
```

**后果**：呼吸灯跑到主循环速度（几十 μs 一步）→ **看起来一直亮着**。

### 6.4 为什么这比"ISR 里直接做业务"好

| 方案 | ISR 内容 | 优点 | 缺点 |
|---|---|---|---|
| **A. ISR 里直接步进** | `s_duty += s_step; PwmSetUs(...)` | 简单 | 业务逻辑在 ISR 里，**难调试**（下断点会打乱节拍） |
| **B. ISR 只加 `g_ms`** | `g_ms++` | **ISR 极短**；一个节拍服务无限个任务；逻辑在主循环**可断点/单步** | 多一层间接 |

**⭐ 这就是 FreeRTOS 的雏形**：

```
FreeRTOS:  SysTick 中断里 xTickCount++
           任务调度器检查"哪个任务的唤醒时间到了"
           
本工程:    TIM4 中断里 g_ms++
           主循环检查"哪个任务的 last_xxx 到点了"
```

**W17 学 RTOS 时，你会看到一模一样的结构。**

### 6.5 32 位 `g_ms` 的溢出

```
2^32 × 1ms ≈ 49.7 天
```

**溢出后 `g_ms - last_xxx` 仍然正确** —— 因为**无符号整数减法会自动处理回绕**：

```
g_ms 从 0xFFFFFFFF 回绕到 0
last = 0xFFFFFF00
0 - 0xFFFFFF00 = 256（无符号运算）→ 正确表示"过了 256ms"
```

**这就是为什么规则 2 要求用减法而不是比较大小。**

## 七、踩坑记录

### 坑 1：PA8 用 `GPIO_CFG_OUT_PP_50MHZ` → PWM 完全无输出

```c
gpio_config(GPIOA, 8, GPIO_CFG_OUT_PP_50MHZ);   /* ❌ 普通推挽 */
gpio_config(GPIOA, 8, GPIO_CFG_AF_PP_50MHZ);    /* ✅ 复用推挽 */
```

| 模式 | 值 | 引脚由谁控制 | 有 PWM 吗 |
|---|---|---|---|
| 普通推挽 `OUT_PP` | `0x3` | 你写 `ODR`/`BSRR` | ❌ |
| **复用推挽 `AF_PP`** | **`0xB`** | **定时器硬件** | ✅ |

**典型错误场景**：PA0（舵机）、PA7（呼吸灯）都写成 `AF_PP` 能用，**PA8 抄的时候漏改成了 `OUT_PP`** → **只有这一路没波形**。

**⭐ 防错口诀**：**"PWM 的引脚永远用 `AF_PP`，不用想别的。"**

### 坑 2：`motor_duty` 用 `uint32_t` 递减 → 下溢

```c
static uint32_t motor_duty = 30;      /* ❌ 无符号 */
static int32_t  motor_step = 20;      /* 会变成 -20 */

motor_duty += motor_step;             /* 10 + (-20) → 4294967286 */
if (motor_duty <= 0) { ... }          /* 不成立，不重置 */
TIMER_PwmSetUs(..., motor_duty);      /* 传天文数字 → CCR 乱码 */
```

**修法**：`int32_t motor_duty` + **钳位**：

```c
motor_duty += motor_step;
if (motor_duty >= 50) { motor_duty = 50; motor_step = -20; }
if (motor_duty <= 0)  { motor_duty = 0;  motor_step =  20; }
```

**⚠️ 只改方向不钳位也不行** —— `motor_duty` 会冲出范围。

**这和 `uint8_t angle += (-45)` 是同一类错误：无符号类型上做减法。**

### 坑 3：`last_breathe += 1` 与阈值 `>= 10` 单位不匹配

见 6.3 规则 1。**这个错在 `6.舵机` 修过一次，复制到 `8.多路PWM` 时又带回来了。**

**⭐ 教训：复制代码时，先搜索所有"魔法数字"，核对单位。**

### 坑 4：`TIMER_Setup` 返回值没检查

```c
TIMER_Setup(TIM1, 1, 50);      /* 返回 0/-1，不看 */
```

**若返回 -1**（参数非法）→ `PSC` 没写 → `tick_of` 返回 0 → 后面的 `PwmSetUs` **除零 → HardFault**。

**修法**：

```c
if (TIMER_Setup(TIM1, 1, 50) != 0)
{
    while (1) { LED_Toggle(); Delay_ms(100); }   /* 故障快闪 */
}
```

**并且要"注入故障"验证**（临时传 `tick_us = 5`，因 `72 % 5 ≠ 0` 返回 -1），**确认错误分支真的进得去**。

## 八、⚠️ 电源问题（电机不转的真正原因）

### 8.1 症状

```
上电 → 电机转了一会 → 停了 → 呼吸灯也停 → 【PC13 的 LED 莫名亮了】
```

### 8.2 诊断过程

| 步骤 | 结果 | 结论 |
|---|---|---|
| **断开电机** | 呼吸灯恢复正常 | ✅ **是电源问题，不是软件** |
| 检查 PC13 | 代码从没碰过 GPIOC | **PC13 被拉低 = 芯片状态异常（门锁/异常复位）** |

**⭐ "PC13 莫名点亮"是最好的诊断线索** —— 正常代码不可能驱动它。

### 8.3 根因：ST-Link 的 5V 带不动电机

| 项 | ST-Link 5V | 直流电机 |
|---|---|---|
| 来源 | USB VBUS | — |
| 电流 | USB 2.0 上限 500mA，ST-Link 自己吃 ~100mA → **剩约 400mA** | 空载 100~300mA，**启动/堵转 0.5~2A** |
| 滤波 | 几乎无 | 需要大电容吸收换向尖峰 |

**结果**：

```
电机启动 → 电流飙到 1A → 5V 跌到 3V 以下
→ STM32 brownout 复位 / 闩锁
→ 主循环死、PC13 被乱写、呼吸灯停
```

### 8.4 修法

| # | 措施 | 说明 |
|---|---|---|
| **1** | **电机用独立电源**（12V 5A 适配器） | **不要用 ST-Link/板子的 5V** |
| **2** | **逻辑地 与 电机地 连在一起** | 不共地 → 控制信号无参考 |
| **3** | **电机电源端并联 220μF 电解 + 0.1μF 瓷片** | 吸收启动电流和换向尖峰 |
| **4** | **电机两端反并联 1N4007 二极管** | 续流，吸收反向电动势 |
| **5** | 占空比从 30% 起步 | 别一上来 100% |

**接线拓扑**：

```
12V 适配器 ──┬── TB6612 VM
             ├── 220μF 电解 + 0.1μF 瓷片 → GND
             └── GND ──┬── TB6612 GND
                       └── STM32 GND     ★ 共地

ST-Link 3.3V ── STM32（只给逻辑供电）
             └── TB6612 VCC
```

### 8.5 ⭐ 最重要的教训

> **做带电机/大电流负载的项目，电源和滤波要一开始就规划，
> 不能等到"发现转不动"再补。**

**电机项目五问**：

```
① 电机电流多大？（启动峰值 = 额定 × 3~8）
② 电源能给多少？（查规格，别猜）
③ 电容加了吗？（至少 220μF 电解 + 0.1μF 瓷片）
④ 续流二极管加了吗？
⑤ 逻辑电源和电机电源分开了吗？共地了吗？
```

## 九、结论

1. **封装的收益在外设变多之后才明显** —— 单外设时收益有限，但一旦有 3~4 个外设，不封装就会失控。
2. **参数用物理量而非寄存器原值** —— 把"算数"收进驱动，调用方只说意图。
3. **`tick_of` 从 PSC 反推，零状态** —— 能从寄存器反推的参数不要另存一份（两份必然不同步）。
4. **通道映射记住两条规律**：`ch ≤ 2 → CCMR1`；奇偶决定位偏移（0 或 8）。
5. **`ARR` 是定时器级共享的** —— 不同频率必须用不同定时器。
6. **非阻塞结构三条规则**：阈值与步进同单位、用减法比较、`last += 周期` 而非 `last = g_ms`。
7. **`g_ms` 节拍模式就是 RTOS 的雏形** —— SysTick + 任务唤醒时间的思路完全一样。
8. **清标志的写法取决于寄存器语义**：`SR` 用 `= ~mask`（W0C）、`PR` 用 `= mask`（W1C）、`ISER` 用 `|=`。
9. **PWM 引脚必须 `AF_PP`** —— 这是最容易"抄漏一个词"的地方。
10. **电源是硬件设计的一部分** —— 电机类项目必须先算电流、先加电容。
