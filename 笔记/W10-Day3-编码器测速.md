# W10 Day3 —— 编码器测速（正交解码）

> 目标：用 TIM 的编码器模式读增量式编码器，实现"位置"和"转速"。
> 交付：正转 5 格 +20，反转 5 格 −20；速度能随转速变化。
> 硬件：EC11 旋转编码器（20 格/圈）

---

## 一、正交编码器的原理

### 1.1 A/B 两相相差 90°

```
正转（顺时针）：
A: ‾‾‾|_____|‾‾‾|_____
B: ‾‾‾‾‾‾|_____|‾‾‾|___
       ↑ A 超前 B 90°

反转（逆时针）：
A: ‾‾‾‾‾‾|_____|‾‾‾|___
B: ‾‾‾|_____|‾‾‾|_____
       ↑ B 超前 A 90°
```

**方向判断的唯一依据：一个边沿到来时，另一相是什么电平。**

| 方向 | A 下降沿到来时，**B 的电平** |
|---|---|
| **正转** | **B = 1（高）** |
| **反转** | **B = 0（低）** |

**⭐ 这个判据是本次实测验证过的**（见第四节波形分析）。

### 1.2 4 倍频是怎么回事

**一个完整的正交周期有 4 个边沿**：

```
A: ‾‾‾|_____|‾‾‾
      ↑     ↑
B: ‾‾‾‾‾‾|_____|‾‾
        ↑     ↑
   ①     ②     ③     ④
 A↓    B↓    A↑    B↑
```

| 计数方式 | `SMS[2:0]` | 每周期计数 |
|---|---|---|
| 只数 A 相边沿（2 倍频） | `010` | 2 |
| 只数 B 相边沿（2 倍频） | `001` | 2 |
| **A、B 都数（4 倍频）** | **`011`** | **4** |

**⭐ 4 倍频不只是"数字变大"，是分辨率提高 4 倍。**

**EC11 转一格（一个 detent）= 一个完整正交周期 → CNT 变化 4。**

## 二、TIM 编码器模式的配置

**用 TIM3（PA6 = CH1，PA7 = CH2）**。

### 2.1 引脚：**上拉输入**

```c
gpio_set(GPIOA, 6);                          /* 先定上拉方向 */
gpio_set(GPIOA, 7);
gpio_config(GPIOA, 6, GPIO_CFG_IN_PULL);
gpio_config(GPIOA, 7, GPIO_CFG_IN_PULL);
```

**⚠️ 和输入捕获（`IN_FLOATING`）不同** —— **EC11 是机械触点，必须上拉，否则悬空时读到随机值。**

### 2.2 `CCMR1`：两个通道都设成"输入"

```c
TIM3->CCMR1 = 0;                             /* 先清空 */
TIM3->CCMR1 |= (0x01UL);                     /* CC1S = 01：IC1 → TI1 */
TIM3->CCMR1 |= (0x01UL << 8);                /* CC2S = 01：IC2 → TI2 */
TIM3->CCMR1 |= (0x0FUL << 4);                /* IC1F = 1111：强滤波 */
TIM3->CCMR1 |= (0x0FUL << 12);               /* IC2F = 1111：强滤波 */
```

**`IC1F` / `IC2F` 是输入滤波器**（EC11 触点会抖动）：

| `ICxF` | 采样频率 | 采样数 |
|---|---|---|
| `0000` | — | 不滤波 |
| `0011` | f_CK_INT | 8 |
| **`1111`** | **f_DTS/32** | **8**（最长） |

### 2.3 ⭐ `SMCR`：**编码器模式的开关**

| `SMS[2:0]`（bit[2:0]） | 模式 |
|---|---|
| `000` | 内部时钟（普通定时器） |
| `001` | 编码器模式 1（TI2 边沿计数） |
| `010` | 编码器模式 2（TI1 边沿计数） |
| **`011`** | **编码器模式 3（TI1 + TI2 都计数 = 4 倍频）** |

```c
TIM3->SMCR = 0x03UL;                         /* SMS = 011 */
```

**⚠️ 这一步最容易漏** —— 不配 `SMCR`，定时器就是普通模式，**CNT 只会按内部时钟一直加，完全不响应 A/B 相**。

**⭐ `SMCR` 名字的由来**：**Slave Mode Control Register** —— **定时器变成外部信号的"从设备"**。

### 2.4 `CCER`：两个通道都使能

```c
TIM3->CCER |= (1UL << 0);                    /* CC1E：使能 TI1 */
TIM3->CCER |= (1UL << 4);                    /* CC2E：使能 TI2 */
```

**⚠️ 两个都要开** —— 4 倍频需要两相都参与。

### 2.5 `ARR`：拉满 0xFFFF

```c
TIM3->ARR = 0xFFFF;                          /* 16 位全范围，当"位置"用 */
```

**为什么拉满**：编码器是用来记**位置**的，`CNT` 应该能连续计数。

### 2.6 启动

```c
TIM3->CR1 |= (1UL << 0);                     /* CEN */
```

## 三、⭐ 读位置的技巧：`int16_t` 差值

**`CNT` 是 16 位，会回绕：** `65535 → 0 → 1 → ...`

**如果逆时针转，`CNT` 从 0 变成 65535，直接用 `uint16_t` 相减会得到巨大的数。**

**解法**：

```c
static uint16_t last_cnt = 0;

uint16_t now   = TIM3->CNT;
int16_t  delta = (int16_t)(now - last_cnt);      /* ★ 关键 */
last_cnt = now;
g_position += delta;
```

**为什么这样对**：

```
正转：last=65535, now=0     → (int16_t)(0 - 65535) = +1  ✅
反转：last=0,     now=65535 → (int16_t)(65535 - 0) = -1  ✅
```

**`int16_t` 的溢出语义恰好等于"有符号回绕"，和编码器的物理行为一致。**

**⭐ 这和 `g_ms` 用无符号差值算时间差是同一个思路，只是一个用有符号、一个用无符号。**

## 四、⭐ 转速公式与定时采样

### 4.1 通用公式（换成电机编码器也能用）

```
转速 = 每秒计数 × 60 / 每圈计数

每圈计数 = 编码器线数 × 倍频 × 减速比
```

**本项目（EC11）**：

```
每圈计数 = 20 格 × 4 倍频 = 80
```

### 4.2 定时采样结构（100ms 一次）

**为什么必须定时采样**：**瞬时速度 = 位置的变化率，必须给定时间窗口才能算。**

```c
/* TIM2 做 100ms 节拍中断 */
TIMER_Setup(TIM2, 2, 100000);                /* 2μs/计数，周期 100ms */
TIMER_EnableUpdateIrq(TIM2, 3);
TIMER_Start(TIM2);

/* 主循环里累计 */
acc += delta;

/* 每 100ms 结算一次 */
if (g_tick_100ms)
{
    g_tick_100ms = 0;

    if (acc != 0)                            /* ★ 只在有转动时更新 */
    {
        g_speed_cps = acc * 10;                                  /* ×10 → 每秒 */
        g_speed_rpm = g_speed_cps * 60 / ENC_COUNTS_PER_REV;
    }
    /* acc == 0（没转动）→ 速度保持上次的值，不清零 */

    acc = 0;
}
```

### 4.3 ⭐ 为什么"只在有转动时更新"

**如果每次都更新（包括 acc = 0）**：

```
转动手柄 → 速度有值
松手 → 下一个 100ms 节拍 acc = 0 → 速度被算成 0
按暂停 → 看到的永远是 0
```

**"只在 acc != 0 时更新"** → **停手后保持最后的值** → **能暂停观察。**

**⚠️ 这是调试可视化的小技巧，不是算法的一部分。** 正式产品里速度应该真实反映"当前为 0"。

### 4.4 采样周期要固定

**为什么必须是固定周期（如 100ms）**：

| 采样周期 | 影响 |
|---|---|
| **固定** | 速度 = `Δ计数 / 固定时间`，可直接换算 |
| **不固定**（比如用 `Delay(10)` 后读） | 每轮耗时不确定 → **速度值会抖** |

**⭐ 这个"固定采样周期"就是后面 PID 的采样周期** —— **W29 学 PID 时会直接用到。**

**这次调试走了 3 小时，前 2.5 小时全在一个"地线没接好"的问题上。**

### 5.1 排查链

| # | 现象 | 检查手段 | 结论 |
|---|---|---|---|
| **1** | `CNT` 完全不动 | 换接线、看 Watch | **面包板 GND 接触不良** → 没共地 |
| **2** | 修 GND 后，正向 +4、反向 −1 | Watch 看 CNT | 怀疑信号质量 |

| **5** | 放大看相位顺序 | 500kHz 采样 + 光标 | **正转 A 先（A↓ 时 B=1）；反转 B 先（A↓ 时 B=0）→ 相位正常** |

| 根因 | 说明 |
|---|---|
| **面包板 GND 接触不良** | A/B 没有低电平参考 → 完全读不到有效边沿 |

**⭐ 两个问题叠加，表现就是"CNT 完全不动"。**

### 5.3 ⭐ 最重要的教训

> **波形分析必须在"接线确认正常"之后做。**
> **用坏接线下的波形去推断"硬件不支持"，会得出完全错误的结论。**

**当时的错误判断**：

```
看到反向波形"两相重合" → 推断"这颗 EC11 输出窄脉冲，
标准 4 倍频解码不适用" → 建议改用软件解码
```

**实际**：**接线修好后，硬件编码器模式完全正常。**

**⭐ 如果当时直接改用软件解码，就永远学不到"TIM 编码器模式"这个知识点。**

## 六、五种定时器用法的对照（**W9-W10 总览**）

| 用法 | 关键寄存器 | 数据流 | 学到的时间 |
|---|---|---|---|
| **PWM 输出** | `CCMR1` 的 `OC1M=110`、`CCER` 的 `CC1E` | 你写 `CCR` → 引脚输出 | W9 Day3 |
| **定时中断** | `DIER` 的 `UIE`、`CR1` 的 `CEN` | 溢出 → ISR | W9 Day2 |
| **输入捕获** | `CCMR1` 的 `CC1S=01`、`CCER` 的 `CC1E` | 引脚边沿 → 硬件写 `CCR` | W10 Day2 |
| **编码器模式** | **`SMCR` 的 `SMS=011`**、`CCMR1` 的 `CC1S/CC2S=01` | **A/B 相 → 硬件加减 `CNT`** | **W10 Day3** |
| **PWM 互补+死区** | `CCER` 的 `CC1NE`、`BDTR` 的 `MOE/DTG` | TIM1 双引脚输出 | W9 Day4 |

**⭐ 核心区别：**

- **PWM / 定时中断 / 输入捕获**：`CNT` 由**内部时钟**驱动（自由运行）
- **编码器模式**：`CNT` 由**外部 A/B 边沿**驱动 ← **`SMCR` 就是切换这个**

## 七、Think 题与答案

| # | 问题 | 答案 |
|---|---|---|
| **1** | `SMS=011`（4 倍频）和 `SMS=001`（2 倍频）除了分辨率还有什么区别？ | **4 倍频对抖动和单个边沿丢失更鲁棒** —— 2 倍频漏一个边沿位置就错，4 倍频还有另一相可以补 |
| **2** | 为什么编码器模式用**上拉输入**，输入捕获用**浮空输入**？ | EC11 是机械触点，**悬空时会读到随机值**；输入捕获的信号源通常是推挽输出（有确定电平），浮空即可 |
| **3** | `IC1F = 1111` 滤波太强会怎样？ | **快速转动时边沿被滤掉** → 丢计数。判据：**快速转和慢速转，每格的计数值应该相同** |
| **4** | 读 `CNT` 差值为什么要用 `int16_t`？ | `uint16_t` 相减在回绕时会得到巨大正数；`int16_t` 的溢出语义等于"有符号回绕"，和物理行为一致 |
| **5** | EC11 一圏 20 格、4 倍频。1 秒转 2 圈时"格/秒"和"rpm"各是多少？ | 格/秒 = 2×20 = **40**；rpm = 2×60 = **120**；计数率 = 40×4 = **160 计数/秒** |

## 八、结论

1. **正交编码看的是"边沿到来时另一相的电平"** —— 这是方向判断的唯一依据。
2. **`SMCR` 的 `SMS=011` 是编码器模式的开关**，漏配就完全不响应 A/B。
3. **`CC1E` 和 `CC2E` 两位都要使能**（4 倍频需要两相）。
4. **EC11 必须上拉输入**（机械触点，悬空不可靠）。
5. **读位置用 `int16_t` 差值** —— 自动处理 16 位回绕。
6. **转速 = 每秒计数 × 60 / 每圈计数**，每圈计数 = 线数 × 倍频 × 减速比。
7. **采样周期必须固定**（用定时器节拍），否则速度值会抖 —— 这也是 PID 的前提。
8. **调试可视化技巧**：速度只在"有转动"时更新，停手保持最后值，方便暂停观察。
9. **⭐ 排查顺序：先电源和地 → 再数边沿次数 → 最后看相位顺序。** 不能跳步。
10. **⭐ 波形分析必须在接线确认正常之后做** —— 否则会推出完全错误的结论。
