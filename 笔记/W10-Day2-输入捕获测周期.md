# W10 Day2 —— 输入捕获测周期

> 目标：用定时器输入捕获测出一路已知频率的信号，并正确处理计数器溢出。
> 交付：1 kHz / 10 Hz / 5 Hz / 1 Hz 四档全部测对（含 15 次溢出）。

---

## 一、原理：硬件帮你打时间戳

```
定时器在数数：CNT = 0 → 1 → 2 → ... → ARR → 0 → ...
                          ↓
引脚上来了一个【上升沿】
                          ↓
【硬件自动】把当前 CNT 复制进 CCR1，并置位 CC1IF（SR 的 bit1）
                          ↓
代码读 CCR1 = "这个边沿发生在第几个计数"
```

**两次捕获的 `CCR1` 相减 = 两个边沿之间的计数差 = 周期（以计数为单位）。**

**⭐ 核心优势**：**打时间戳是硬件做的，精度 = 计数精度，不受软件响应延迟影响。**

**对比**：如果靠 GPIO 中断 + 软件记时间，中断响应延迟（~1μs）会直接叠加到测量误差里。

---

## 二、配置：输入捕获 vs PWM 的区别

### 2.1 引脚模式：**输入，不是复用推挽**

| 用途 | 引脚模式 |
|---|---|
| **PWM 输出** | `GPIO_CFG_AF_PP_50MHZ`（复用推挽，引脚交给定时器**输出**） |
| **输入捕获** | **`GPIO_CFG_IN_FLOATING`**（浮空输入，定时器**读**引脚电平） |

```c
gpio_config(GPIOA, 6, GPIO_CFG_IN_FLOATING);   /* PA6 = TIM3_CH1 */
```

**⚠️ 这里最容易搞混** —— PWM 用 `AF_PP`，输入捕获反而用普通输入模式。

### 2.2 `CCMR1`：把通道从"输出"改成"输入"

**`CC1S[1:0]` 决定通道方向**：

| `CC1S` | 模式 | 说明 |
|---|---|---|
| `00` | **输出**（比较/PWM） | 定时器 → 引脚 |
| **`01`** | **输入，映射到 TI1** | **引脚 → 定时器（输入捕获）** |
| `10` | 输入，映射到 TI2（交叉） | — |
| `11` | 输入，映射到 TRC | — |

```c
TIM3->CCMR1 &= ~0x000FUL;      /* 清 CC1S[1:0] + IC1PSC[1:0] */
TIM3->CCMR1 |=  0x01UL;        /* CC1S = 01：输入模式，映射 TI1 */
```

**另外两个字段**：

| 字段 | 位 | 值 | 作用 |
|---|---|---|---|
| `IC1PSC[1:0]` | bit[3:2] | **`00`** | 每个边沿都捕获（不分频） |
| `IC1F[3:0]` | bit[7:4] | **`0000`** 或 `0011` | **输入滤波器** |

**`IC1F` 说明**：

| `IC1F` | 采样/滤波 | 延迟（f_CK_INT = 1MHz 时） |
|---|---|---|
| `0000` | 不滤波 | 0 |
| `0011` | 8 个采样 | ~8 μs |

**⚠️ 滤波会引入延迟，但周期测量里两个边沿延迟相同 → 差值不受影响**。**只有测"绝对时刻"时才需要补偿。**

### 2.3 `CCER`：选边沿 + 使能

| 位 | 名称 | 值 | 含义 |
|---|---|---|---|
| bit0 | `CC1E` | **1** | 使能捕获 |
| bit1 | `CC1P` | **0** | **上升沿**（1 = 下降沿） |

```c
TIM3->CCER &= ~(1UL << 1);     /* CC1P = 0，上升沿 */
TIM3->CCER |=  (1UL << 0);     /* CC1E = 1，使能 */
```

### 2.4 中断使能

```c
TIM3->DIER |= (1UL << 0) | (1UL << 1);   /* UIE（溢出）+ CC1IE（捕获）*/
NVIC_IPR[IRQ_TIM3]  = 0x40;              /* 优先级 4 */
NVIC_ISER0 |= (1UL << IRQ_TIM3);         /* IRQ 29 */
```

### 2.5 ⭐ 精度 vs 溢出范围的取舍

**`PSC` 决定"1 个计数 = 多少时间"，也就同时决定了精度和溢出周期**：

| `PSC` | 计数频率 | 计数精度 | **溢出周期**（ARR=65535） | 适合 |
|---|---|---|---|---|
| **0** | 72 MHz | **13.9 ns** | **0.91 ms** | 高速（> 1.1 kHz） |
| 71 | 1 MHz | 1 μs | **65.5 ms** | 中低速 |
| 719 | 100 kHz | 10 μs | 655 ms | 极低速 |

**⚠️ 精度越高 → 溢出越快 → 溢出处理越关键。**

**本项目用 `PSC = 71`（1μs/计数，65.5ms 溢出）** —— 测 1Hz 时会溢出 15 次。

## 三、⭐ 溢出处理（最容易漏的一环）

### 3.1 问题

**CNT 是 16 位**：`0 → 65535 → 0`（回绕）

**如果两个边沿的间隔超过 65536 个计数**：

```
边沿1 发生在 CNT = 60000
【计数器溢出，回到 0】
边沿2 发生在 CNT = 5000

直接相减：5000 − 60000 = −55000
          无符号解释 → 60536 → 【完全错误】
正确：(65536 + 5000) − 60000 = 10536
```

### 3.2 解法：溢出计数 + **时间戳快照**

```c
static volatile uint32_t g_cap_val;      /* 捕获到的 CCR1 */
static volatile uint32_t g_cap_ovf;      /* 捕获那一刻的溢出计数（快照）*/
static volatile uint32_t g_overflow_cnt; /* 实时溢出计数 */
static volatile uint8_t  g_cap_flag;

void TIM3_IRQHandler(void)
{
    /* ① 捕获中断 */
    if (TIM3->SR & (1UL << 1))                      /* CC1IF */
    {
        TIM3->SR = (uint16_t)~(1UL << 1);           /* 只清 CC1IF */
        g_cap_val = TIM3->CCR1;
        g_cap_ovf = g_overflow_cnt;                 /* ★ 同一时刻快照 */
        g_cap_flag = 1;
    }

    /* ② 溢出中断 */
    if (TIM3->SR & (1UL << 0))                      /* UIF */
    {
        TIM3->SR = (uint16_t)~(1UL << 0);           /* 只清 UIF */
        g_overflow_cnt++;
    }
}
```

### 3.3 三个必须理解的点

#### ① 为什么要"快照"

```c
/* ❌ 错的：主循环里读 g_overflow_cnt */
g_cap_val = TIM3->CCR1;              /* t1 时刻 */
...
delta = g_overflow_cnt * 65536 + ...  /* t2 时刻，值可能已经变了 */
```

**捕获发生在 t1，主循环读溢出计数在 t2** → **两个量来自不同时刻** →
低频时如果中间又溢出了，就会多算或少算 65536。

**必须在捕获的那一瞬间把两个量一起存下来。**

#### ② 为什么用 `ovf_delta` 而不是"清零"

```c
/* ✅ 用差值 */
uint32_t ovf_delta = g_cap_ovf - last_ovf;
last_ovf = g_cap_ovf;

/* ❌ 用清零 */
g_overflow_cnt = 0;    /* 清零和捕获不对齐 → 可能丢掉清零瞬间的溢出 */
```

**差值法不需要清零，天然安全** —— 和 `g_ms` 回绕同理（无符号减法自动处理）。

#### ③ 为什么 `SR` 要用 `= ~mask` 而不是 `&= ~mask`

```c
TIM3->SR &= ~(uint16_t)(1UL << 1);      /* ❌ 读-改-写 */
TIM3->SR  = (uint16_t)~(1UL << 1);      /* ✅ 一条 STR，原子 */
```

**在一个 ISR 里依次处理 CC1IF 和 UIF 时，`&= ~` 尤其危险**：
清 CC1IF 的读-改-写期间，硬件可能刚置位 UIF，写回旧值会**把 UIF 一起清掉** → 丢一次溢出。

**丢一次溢出 = 周期少算 65536μs。**

### 3.4 周期计算

```c
uint32_t cap = g_cap_val;
uint32_t ovf = g_cap_ovf;

uint32_t ovf_delta = ovf - last_ovf;
uint32_t delta = ovf_delta * 65536UL + (cap - last_cap);

last_cap = cap;
last_ovf = ovf;

if (delta != 0)                     /* ★ 防除零 */
{
    g_period_us = delta * tick_us;  /* tick_us = 1 时就是 delta */
    g_freq_hz   = 1000000UL / g_period_us;
}
```

**⚠️ `delta != 0` 的保护是必须的** —— 两次捕获的 CCR 相同时（比如信号频率恰好是计数频率的整数倍）会除零 → HardFault。

## 四、实测数据

**测试装置**：TIM2_CH1（PA0）输出方波 → 杜邦线短接 → PA6（TIM3_CH1）输入捕获。
**逻辑分析仪**先确认 PA0 的输出频率，再用 Watch 看 `g_period_us` / `g_freq_hz`。

| 输入频率 | 理论周期 | 折算计数（1μs） | **溢出次数** | 测得 `g_period_us` | 测得 `g_freq_hz` | 结论 |
|---|---|---|---|---|---|---|
| **1 kHz** | 1 000 μs | 1 000 | **0** | 1 000 | **1 000** | ✅ |
| **10 Hz** | 100 000 μs | 100 000 | **1** | 100 000 | **10** | ✅ |
| **5 Hz** | 200 000 μs | 200 000 | **3** | 200 000 | **5** | ✅ |
| **1 Hz** | 1 000 000 μs | 1 000 000 | **15** | 1 000 000 | **1** | ✅ |

### 溢出次数验算

```
10 Hz：100 000 / 65 536 = 1.53  → 溢出 【1】 次
5  Hz：200 000 / 65 536 = 3.05  → 溢出 【3】 次
1  Hz：1 000 000 / 65 536 = 15.26 → 溢出 【15】次
```

### 为什么 1 Hz 那次最关键

**15 次溢出，只要漏掉 1 次，结果就会从 `1 Hz` 变成：**

```
delta = 14 × 65536 + 16960 = 934464
freq  = 1000000 / 934464 = 1.07 Hz
```

**测出精确的 `1` → 一次都没漏 → 溢出处理完全正确。** ✅

**⚠️ 1 kHz 测对了【不能】证明溢出处理正确** —— 1000 个计数远小于 65536，**根本没有溢出发生**。**必须用 < 15 Hz 的信号才能验证。**

## 五、踩坑记录

### 坑 1：`TIMER_Setup` 的 `72 % tick_us != 0` 检查过严（**驱动设计缺陷**）

**现象**：

```c
TIMER_Setup(TIM2, 10, 100000);      /* 想输出 10Hz */
/* → 返回 -1，PSC/ARR 一个都没写 */
/* → TIM2 完全没配置 → 无波形 → 捕获也测不到任何东西 */
```

**根因**：`72 % 10 = 2 ≠ 0` → 检查不通过。

**但"tick_us 必须整除 72"这个前提本身是错的**：

```
PSC = 72 × tick_us − 1        （永远是整数）
(PSC + 1) / 72 = tick_us      （整数除法永远精确）
```

**例**：`tick_us = 10` → `PSC = 719` → `(719+1)/72 = 10` ✅ 完全正确

**唯一真实的约束是 `PSC ≤ 65535`**：

```
72 × tick_us − 1 ≤ 65535  →  tick_us ≤ 910
```

**修法**：

```c
/* 旧：if (72 % tick_us != 0) return -1;              ❌ 无根据 */
/* 新：if (tick_us > 910)     return -1;              ✅ 真正的约束 */

if (tick_us == 0)                  return -1;   /* 挡除零 */
if (tick_us > 910)                 return -1;   /* PSC ≤ 65535 */
if (period_us % tick_us != 0)      return -1;   /* 周期必须是整数个 tick */
if (period_us / tick_us > 0x10000) return -1;   /* ARR ≤ 65535 */
```

**修复后被解锁的用法**（原来全被挡住）：

| 想要的分辨率 | 修之前 | 修之后 |
|---|---|---|
| 5 μs / 10 μs / 20 μs / 100 μs / 500 μs | ❌ | ✅ |

**⭐ 教训**：**给接口加限制前，先推导这个限制是否真实存在。** 加了不必要的前提，会把一半的合法用法挡在门外。

### 坑 2：没检查 `TIMER_Setup` 返回值 → 静默失败

```c
TIMER_Setup(TIM2, 10, 100000);      /* 返回 -1，没人看 */
```

**后果**：程序照常往下跑，但定时器根本没配置 → **无线索可查**。

**修法**：

```c
if (TIMER_Setup(TIM2, 10, 100000) != 0)
{
    while (1) { LED_Toggle(); Delay_ms(100); }    /* 故障快闪 */
}
```

**⭐ 如果这次有返回值检查，5 分钟前就知道是"配置失败"，而不是去查波形。**

**而 `TIMER_Setup` 本来就返回 `int`（0 / -1）—— 设计者给你返回值，就是为了让你检查的。**

### 坑 3：`SR` 用 `&= ~` 清标志

```c
TIM3->SR &= ~(uint16_t)(1UL << 1);      /* ❌ 读-改-写 */
TIM3->SR  = (uint16_t)~(1UL << 1);      /* ✅ 直接赋值 */
```

**TIM->SR 是 W0C 寄存器**，见 3.3 ③。

### 坑 4：`delta == 0` 没保护 → 除零 HardFault

```c
g_freq_hz = 1000000UL / delta;    /* delta = 0 → HardFault */
```

**什么情况 `delta = 0`**：**两次捕获的 CCR 相同** —— 比如信号频率恰好等于计数频率的整数倍，或者捕获到了重复边沿。

**必须** `if (delta != 0)` 保护。

## 六、输入捕获 / PWM 的寄存器对比

**同一个通道，`CC1S` 不同，方向就相反**：

| 项 | **PWM 输出** | **输入捕获** |
|---|---|---|
| 引脚模式 | `AF_PP`（复用推挽） | **`IN_FLOATING`**（浮空输入） |
| `CC1S[1:0]` | **`00`**（输出） | **`01`**（输入，TI1） |
| `OC1M` / `IC1F` | `OC1M = 110`（PWM 模式 1） | `IC1F`（输入滤波） |
| `CC1E` | 1（输出使能） | 1（捕获使能） |
| `CC1P` | 0（高有效） | 0（上升沿捕获） |
| `CCR1` 的作用 | **你写**（占空比） | **硬件写**（时间戳） |
| 中断 | 通常不用 | **CC1IE**（每次捕获触发） |

**⭐ 最关键的一句**：**`CCR1` 在输出模式是你写、在输入模式是硬件写。** 同一个寄存器，两个方向的数据流相反。

## 七、思考题与答案

| # | 问题 | 答案 |
|---|---|---|
| **1** | 为什么输入捕获引脚用 `IN_FLOATING` 而 PWM 用 `AF_PP`？ | 方向不同：PWM 是定时器**输出**到引脚（需复用），捕获是定时器**读**引脚（普通输入） |
| **2** | `CC1S` 从 `00` 改成 `01` 后，同一个通道还能输出 PWM 吗？ | **不能** —— 一个通道同一时刻只能是输入或输出之一 |
| **3** | 信号有毛刺时 `IC1F` 设多大？ | 按毛刺宽度选，一般 `IC1F = 0011`（8 采样）；**代价是引入 ~8μs 延迟**，测周期时两边延迟相消 |
| **4** | `PSC=0`（72MHz 计数）时最低能测多少 Hz？ | 理论上受 `uint32_t` 溢出计数上限限制：`4.29e9 × 0.91ms ≈ 40 天`。**实际受"多久没边沿就认为无信号"的超时判断限制** |
| **5** | 信号频率从 1kHz 突变到 10Hz，上一次时间戳还有效吗？ | **第一个周期会算错**（跨了两种频率）。要**丢弃突变后的第一次结果**，或加合理性检查 |

## 八、结论

1. **输入捕获的原理是"硬件打时间戳"** —— 精度等于计数精度，不受软件延迟影响。
2. **输入捕获用 `IN_FLOATING` + `CC1S=01`**，和 PWM 的 `AF_PP` + `CC1S=00` 完全相反。
3. **溢出处理是 W10 最容易漏的一环** —— 必须 ① 累加溢出计数 ② **捕获时同时快照** ③ 用差值而非清零。
4. **`SR` 用 `= ~mask`（W0C），不能用 `&= ~mask`** —— 多条标志共用一个寄存器时，读-改-写会误清。
5. **验证溢出必须用低频（< 15 Hz）** —— 1kHz 测对了证明不了溢出处理对。
6. **`TIMER_Setup` 的 `72 % tick_us` 检查是无根据的限制** —— 真实约束只有 `PSC ≤ 65535`（`tick_us ≤ 910`）。
7. **一定要检查返回值** —— 否则配置失败会静默无声，排查方向全歪。
8. **`delta == 0` 的除零保护不能省**。
