## 二、机械按键抖动

### 现象与原因

**按下/松开的瞬间，金属触点会物理弹跳**，引脚电平在短时间内反复跳变。

```
 电平  1 ──┐  ┌─┐ ┌──┐  ┌──────────────
           │  │ │ │  │  │
         0 ┘  └─┘ └──┘  └──────────────
           ↑        ↑
       第一下    真正稳定
       接触     (约 5~20ms 后)
```

| 项 | 值 |
|---|---|
| **抖动时长** | **约 5 ~ 20 ms**（每次按都不一样） |
| **原因** | 机械特性（触点弹跳），不是电路问题 |
| **软件能否避免** | 不能消除，只能"忽略"（消抖） |

### 不消抖会怎样（实测现象）

**观察到的**：有时候没完全按下，也被判定为按下，LED 随即亮起。

**更典型的后果**（"按一下切换"写法下）：**一次按下被识别成多次翻转**，LED 乱跳。

---

## 三、消抖的**三步**（标准做法）

| 步骤 | 做法 | 解决什么 |
|---|---|---|
| **① 延时等待** | 检测到电平变化后 `Delay_ms(10~20)` | 等抖动过去 |
| **② 二次确认** | 再读一次，电平仍一致才算真的 | 排除瞬时毛刺 |
| **③ 等松手**（或边沿检测） | 动作执行后 `while(仍按下){}` | **排除"按住不放"的重复触发** |

### ⚠️ 为什么"只延时确认"不够（第三步的必要性）

```c
/* 只有前两步 */
while (1)
{
    if (gpio_read(GPIOA, 5) == 0)      /* 按住不放 → 每一圈都成立 */
    {
        Delay_ms(20);
        if (gpio_read(GPIOA, 5) == 0)
            gpio_toggle(GPIOA, 12);     /* ← 每 20ms 翻转一次！ */
    }
}
```

**结果：按住 1 秒，LED 翻转约 50 次。**

**原因**：前两步只管"确认这次按下是真的"，**没管"这次按下是不是已经处理过了"**。按住不放时，主循环每一圈都满足条件 → 重复触发。

**所以必须加第三步**：`while (仍按下) {}`（阻塞等松手），或者用**边沿检测**（记录上次状态，只在"松开→按下"的瞬间触发）。

## 四、上拉输入 vs 下拉输入

### 接法与电平

| 模式 | 电路 | 松开读到 | 按下读到 |
|---|---|---|---|
| **上拉输入** | `IO ── 按键 ── GND` | **1** | **0** |
| **下拉输入** | `IO ── 按键 ── 3.3V` | **0** | **1** |

### 内部上下拉靠 ODR 决定

```
CRL/CRH 配置 CNF=10, MODE=00  →  "上拉/下拉输入"模式
然后方向由 ODR 决定：
    ODR 对应 bit = 1  →  上拉
    ODR 对应 bit = 0  →  下拉
```

```c
/* 内部上拉，不需要外接电阻 */
gpio_set(GPIOA, 5);                          /* ODR[5] = 1 → 上拉 */
gpio_config(GPIOA, 5, GPIO_CFG_IN_PULL);     /* CNF=10, MODE=00 */

/* 内部下拉 */
gpio_reset(GPIOA, 5);                        /* ODR[5] = 0 → 下拉 */
gpio_config(GPIOA, 5, GPIO_CFG_IN_PULL);
```

### 重要：ODR 是**实时**决定方向，不是配置时锁存

## 五、`gpio_read` 实现

```c
static inline uint32_t gpio_read(GPIO_TypeDef *port, uint32_t pin)
{
    if ((port->IDR & (1UL << pin)) == 0)
        return 0;
    else
        return 1;
}
```

**要点**：
- 读的是 **`IDR`**（输入数据寄存器），不是 ODR
- `IDR & (1<<pin)` 得到的是 `0` 或 `1<<pin`，**必须归一化成 0/1**

**等价的位运算写法**：`return (port->IDR >> pin) & 1U;`

## 六、已知缺点（改进方向）

### 1. 阻塞式延时让主循环变慢

现在的写法：

```c
if (...) { Delay_ms(20); ... }
```

**每次判断要卡 20ms** → 主循环频率只有 ~50Hz。现在只有按键+LED 无所谓，**以后加串口/定时器/多任务就是灾难**。

### 2. 不阻塞的消抖（状态机，以后用）

```c
/* 每 1ms 调用一次，用计数器代替 Delay */
static uint8_t stable = 1;    /* 稳定后的状态 */
static uint8_t cnt = 0;

uint8_t raw = gpio_read(GPIOA, 5);
if (raw != stable)
{
    if (++cnt >= 20) { stable = raw; cnt = 0; }   /* 连续 20ms 一致才认 */
}
else
{
    cnt = 0;                                       /* 中途变了，重新计数 */
}
```

**这个写法不阻塞**，可放进 1ms 定时器（W8 学定时器后可实现）。

### 3. 等松手是"死等"

```c
while (gpio_read(GPIOA, 5) == 0) { }
```

**如果按键卡住（机械故障），程序会永远卡在这里。** 实际产品会加超时保护。
