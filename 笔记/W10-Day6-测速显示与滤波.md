## 一、实验设计（为什么不用手转）

**用手转 EC11 做不出可量化的对比**：

```
手转 1 格/秒 → 4 计数/秒
采样周期 10ms → 每窗口 delta = 0.04 个计数
→ 原始值：0, 0, 0, 75, 0, 0, 0, 0, 75, ...
→ 滤波后约 7，但"真值"到底多少？无法验证
```

**改用 TIM2 输出的固定频率方波做信号源** —— 频率精确已知，理论值可算。

## 1.1 理论预期

```
TIM2_CH1 (PA0) 输出 5128 μs 周期 → 194.97 Hz
PA0 短接 PA6（编码器 A 相）

A 相每周期 2 个边沿 → 389.94 边沿/秒
每 10ms 的 delta = 3.8994 → 在 3 / 4 之间跳

rpm10 = delta × 150000 / (20 × 10) = delta × 750
  delta = 4 → 3000（300.0 rpm）
  delta = 3 → 2250（225.0 rpm）
  平均 → 2925

理论真值：389.94 × 60 / 80 = 292.4 rpm → rpm10 = 【2924】
```

**⭐ 这本来是完美的滤波实验：原始值 2250↔3000 跳（±14%），滤波后收敛到 2925，理论 2924。**

## 二、⭐ 核心发现：**4 倍频下，"单相方波 + 另一相固定"会被完全抵消**

### 2.1 现象

**配置：`SMS = 011`（4 倍频），PA0—PA6 短接，PA7 悬空（内部上拉）。**

| 变量 | 实测 |
|---|---|
| `dbg_raw` | 0（暂停瞬间）|
| `dbg_ma` | 93 |
| **`dbg_min`** | **−750** |
| **`dbg_max`** | **+750** |
| **`dbg_avg`** | **0** |

### 2.2 ⭐ 诊断：这是"抵消"，不是"没信号"

```
rpm10 = delta × 750
→ dbg_min/max = ±750 意味着 delta 只取 ±1
→ 正负完全对称、平均【精确为 0】
```

**如果是"完全没信号"，`min`/`max` 都会是 0。**
**能看到 ±750，说明边沿确实来了，但方向在交替。**

### 2.3 为什么抵消 —— 状态机分析

**4 倍频（编码器模式 3）的状态序列**：

```
(A,B) 状态：11 → 01 → 00 → 10 → 11     每步 +1（正转）
            11 → 10 → 00 → 01 → 11     每步 −1（反转）
```

**如果 B 固定为 1，A 只能在这两个状态间来回**：

```
11 → 01   ：+1
01 → 11   ：−1      ← 反着走
------------------------
净变化    ：【0】
```

**⭐⭐ 结论：正交解码的本质是"A、B 的相位关系"。单相方波没有相位信息，4 倍频必然抵消。**

**⭐ 这是"很多人不知道"的前提** —— 误以为"接一相也能计数"。

### 2.4 ⭐ 诊断签名（记住这个）

| 观测 | 含义 |
|---|---|
| **`min` 和 `max` 对称（±750）** | **有边沿** |
| **`avg` 精确为 0** | **正负完全抵消** |
| 两者同时出现 | **"方向交替"的确定信号** |

**⭐ 对比：如果 `min = max = 0`，那才是"完全没信号"。**

## 三、改用 2 倍频（`SMS = 010`）

### 3.1 原理

**`SMS = 010`（编码器模式 2）的规则**：

> **数 TI1 的边沿，方向由 TI2 的电平决定**

**TI2 固定为高 → 所有 TI1 边沿都按同一方向计数** ✅

```
A 上升沿（TI2 = 1）→ +1
A 下降沿（TI2 = 1）→ +1      ← 同向！
→ 每周期 +2
```

### 3.2 配置

```c
tim->CCMR1 = 0;
tim->CCMR1 |= (0x01UL);                      /* CC1S = 01：IC1 → TI1（计数用）*/
tim->CCMR1 |= (0x01UL << 8);                 /* CC2S = 01：IC2 → TI2（判方向用）*/
tim->CCMR1 |= (0x0FUL << 4);                 /* IC1F = 1111 */
tim->CCMR1 |= (0x0FUL << 12);                /* IC2F = 1111 */

tim->SMCR  = 0x02UL;                         /* ★ SMS = 010：数 TI1，方向看 TI2 */

tim->CCER |= (1UL << 0);                     /* CC1E */
tim->CCER |= (1UL << 4);                     /* CC2E */
```

**⚠️ `CC2S` / `CC2E` 不能省略** —— **方向和计数的判据都要读 TI2 的电平。**

### 3.3 三种 `SMS` 的对照（**最容易搞混**）

| `SMS` | 模式 | **数哪个引脚的边沿** | 方向由谁判 |
|---|---|---|---|
| **`001`** | 编码器模式 1 | **TI2** | TI1 电平 |
| **`010`** | 编码器模式 2 | **TI1** | TI2 电平 |
| **`011`** | 编码器模式 3（4 倍频）| TI1 **和** TI2 | 互相判 |

**⭐ 记忆法：`001` 里的 "1" 指"模式 1"，不是"通道 1"。想数 TI1 要用 `010`。**

## 五、滑动平均滤波器（**代码已完成，未实测**）

### 5.1 实现

```c
#define MA_N 8

static int32_t s_ma_buf[MA_N];
static uint8_t s_ma_idx = 0;
static int32_t s_ma_sum = 0;

static int32_t MA_Push(int32_t v)
{
    s_ma_sum -= s_ma_buf[s_ma_idx];      /* 减去最老的 */
    s_ma_buf[s_ma_idx] = v;              /* 存入新的 */
    s_ma_sum += v;
    s_ma_idx = (uint8_t)((s_ma_idx + 1) % MA_N);
    return s_ma_sum / MA_N;
}
```

**⭐ 关键：用"滚动累加和"而不是每次重新求和** —— O(1) 而不是 O(N)。

### 5.2 群延迟（**滤波的代价**）

```
延迟 = (N-1)/2 × T = (8-1)/2 × 10ms = 【35 ms】
```

**⚠️ 真实转速变化后，`dbg_ma` 要过 35ms 才反映出一半。**

**对 PID 的影响**：

| 项 | 影响 |
|---|---|
| **相位滞后** | 35ms 延迟 → 10Hz 处约 12.6° 相位滞后 → **降低相位裕度** |
| **微分项** | D 项对延迟最敏感 → **滤波 + 微分容易振荡** |

**⭐ 这就是"滤波强度 vs 响应速度"的永恒矛盾** —— 和 Day 4 的"采样周期"是同一类权衡。

### 5.3 `MA_N` 的经验值

**`N ≤ 系统时间常数的 1/10`**

**电机机械时间常数约 100ms → N ≤ 10 个 10ms 样本。**

| `MA_N` | 群延迟 | 残余波动 |
|---|---|---|
| **1**（不滤波） | 0 | ±750（±14%）|
| 2 | 5 ms | ±375 |
| 4 | 15 ms | ±180 |
| **8** | **35 ms** | **±80** |
| 16 | 75 ms | ±40 |

**⚠️ 这张表是理论预期，未经实测。**

## 六、⭐ 滤波不能解决"量化误差"（重要认知）

**如果信号速率太低（如 EC11 手转），原始值大部分是 0**：

```
raw:  0, 0, 0, 75, 0, 0, 0, 0, 75, 0, ...
MA8:  0, 0, 0, 9, 9, 9, 9, 9, 19, 19, ...
```

**滤波只是"把抖动变平滑"，不能提高分辨率** —— **真值 3 rpm，MA 后也只有约 7 rpm（偏差 130%）。**

**⭐ 两个完全不同的问题：**

| 问题 | 表现 | 解法 |
|---|---|---|
| **噪声**（随机抖动）| 值在真值附近乱跳 | **滤波** ✅ |
| **量化误差**（分辨率不足）| 值偏离真值系统性地 | **加长采样窗口 / 提高分辨率** ❌ 滤波无效 |

**⭐⭐ 很多人以为"滤波能解决一切测量问题"，其实只能解决噪声。**

## 七、踩坑记录

### 坑 1：`SMS = 001` 数的是 TI2，不是 TI1

**最初想把 4 倍频降到 2 倍频，改成了 `SMCR = 0x01`。**

**结果**：`SMS=001` 数 TI2（PA7）的边沿 → PA7 悬空没有边沿 → **完全不计数。**

**⭐ 正确：想数 TI1 要用 `SMS = 010`。**

### 坑 2：注释掉 `CC2S` / `CC2E` 导致 TI2 不在输入模式

```c
//tim->CCMR1 |= (0x01UL << 8);      /* CC2S 被注释 */
//tim->CCER |= (1UL << 4);          /* CC2E 被注释 */
```

**后果**：`CC2S = 00` → **通道 2 变成输出模式**（虽然 `CC2E=0` 没真输出，但 TI2 不再是输入）→ **方向判据失效**。

**⭐ 编码器模式（任何一档）都需要两相都作为输入** —— 即使只数一相。

### 坑 3：`SMS=011` + 单相方波 → 计数抵消（见第二节）

### 坑 4：3.3V 接错到相邻引脚（**未验证，但最可能**）

**PA6 和 PA7 相邻，容易把 3.3V 插到 PA6 上** → 信号源被短路 → 全 0。

**⭐ 教训：调试时用不同颜色的线区分"信号线"和"固定电平线"。**

## 八、结论与待办

### 8.1 已确认的结论

1. **`SMS` 三个值最容易搞混**：`001`→TI2、`010`→TI1、`011`→两者。
2. **编码器模式必须两相都作为输入**（`CC2S=01` + `CC2E=1` 不能省）。
3. **⭐ 4 倍频下单相方波会完全抵消** —— 正交解码的前提是"A、B 的相位关系"。
4. **⭐ 抵消的诊断签名：`min`/`max` 对称、`avg` 精确为 0。**
5. **滤波解决噪声，不解决量化误差** —— 两个不同的问题。
6. **滑动平均的代价是群延迟 `(N-1)/2 × T`** —— 滤波强度与响应速度永恒矛盾。
